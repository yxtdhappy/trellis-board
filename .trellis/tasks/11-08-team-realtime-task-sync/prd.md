# 客户端任务实时上报与广播

## Goal

复用单机 watcher 核心，在团队客户端监听已批准关联项目的 `.trellis`，把尚未 commit 的任务状态变化上报服务端，并由服务端广播给团队其他客户端。

## Background

- 单机 watcher 位于 `server/watcher.js`，监听 `.trellis/tasks`、`.trellis/workspace` 和 `.trellis/.developer`。
- sidecar 已有项目绑定、设备凭据、SSE 事件流和 Git 同步能力。
- 团队 Board 已有 `task.updated`、`sync.required` 等事件类型，但需要扩展为可承载客户端未提交任务内容的准实时协议。
- 未提交文件内容没有 Git commit 作为天然版本，必须设计服务端版本号、幂等键和冲突处理。

## Requirements

- 复用单机 watcher 的目录过滤、递归监听、事件归一化和防抖思路；如需重构，只提取共享核心，不复制实现。
- watcher 在单机 Board 服务端和团队客户端 sidecar 两种运行宿主中可配置回调。
- 团队服务端不启动 watcher；团队客户端只为 approved agent binding 启动 watcher。
- `read_only` 绑定启动接收和本地应用流程，但关闭本地变化上报。
- 客户端把变更归一化为任务级上报，至少携带项目、绑定、任务标识、变化文件、内容或内容摘要、客户端序号和幂等键。
- 客户端可以上报未提交文件内容，不要求用户先 commit 或 push。
- 服务端需要按项目维护实时任务覆盖层或等价机制，让 Board 查询在 Git 重新同步前也能看到最新任务状态。
- 实时文件状态保留到 Git 中同一路径内容与其摘要一致；Git 内容不同或更旧时不得覆盖实时状态。
- 服务端接收顺序即为权威顺序；客户端不得用较旧版本覆盖服务端较新版本。
- 服务端按请求到达顺序串行分配单调版本；并发修改以最后成功到达的版本为最终最新版本。
- 并发合并按文件执行；不同文件互不覆盖，同一文件的冲突由后到版本覆盖。
- 服务端校验上报身份、绑定状态、项目权限、路径范围、文件类型、大小和速率限制。
- 正常网络下，从来源端文件保存完成到目标端 Board 和本地文件完成更新，P95 不超过 3 秒。
- 服务端成功接收后向相同项目其他客户端广播；发送者不重复接收自己的事件。
- 客户端接收事件后刷新 Board，并把服务端最新任务文件写入本地 `.trellis`。
- 写入本地前要比较本地内容和服务端版本；内容不同时保存被覆盖文件的本地备份，再执行服务端权威覆盖。
- 冲突提示必须说明任务、远端版本、本地备份位置和“一键复原”入口。
- 一键复原必须把备份内容作为新的服务端版本上传并广播，不能只留下临时本地分叉。
- 同一任务已有责任人时，非责任人发起任务修改或阶段推进必须收到显眼提醒，展示责任人并建议沟通。
- “继续推进”保留原责任人并记录审计；只有显式选择“接管任务”才变更责任人。
- 警告必须由发起修改的客户端阻断上报；原责任人只接收通知，不要求其在线确认。
- 用户取消时，客户端在备份本地改动后恢复为当前服务端版本，避免本地长期分叉和 watcher 重复提示。
- 断线重连后必须补拉遗漏版本，不能用永久丢失的 best-effort 事件。
- 同一任务并发修改必须有明确、可观察、可测试的冲突结果。
- Git 同步成功后需要把实时覆盖层与 commit 内容收敛，避免长期显示过期状态。

## Acceptance Criteria

- [ ] 单机模式 watcher 行为无回归。
- [ ] 团队 Board 服务端启动时 watcher 状态为 disabled。
- [ ] 成员身份和 Git 强校验产生的有效绑定自动启动 watcher；撤销或失效绑定不启动。
- [ ] `read_only` 绑定不启动上传 watcher，但能接收并应用服务端实时文件。
- [ ] 本地修改未提交的 `task.json` 或 Trellis 状态文件后，服务端在约定时间内收到归一化上报。
- [ ] 同一文件连续快速保存会合并为有界次数的上报，不产生事件风暴。
- [ ] 上报携带可验证的幂等键；重复投递不会重复推进任务。
- [ ] 越界路径、未授权项目、已撤销设备和超大文件被服务端拒绝。
- [ ] 客户端 B 在客户端 A 修改后无需 Git 轮询即可看到任务状态变化。
- [ ] P95 端到端同步时延不超过 3 秒，测量起点为来源端保存完成，终点为目标端本地文件落盘且 Board 可见。
- [ ] 客户端 B 本地 `.trellis` 文件自动变为服务端最新版本。
- [ ] 本地内容与远端不同且将被覆盖时，自动保存备份并显示冲突提示。
- [ ] 一键复原能从本地备份恢复，创建新的服务端版本，并广播到其他客户端。
- [ ] 非责任人修改有责任人的任务时出现显眼提示，包含责任人、继续、取消和接管动作。
- [ ] “继续推进”保留原责任人并有审计记录；“接管任务”显式变更责任人。
- [ ] 取消警告后，本地改动先备份，再恢复为服务端当前版本。
- [ ] 原责任人收到通知，但其他客户端不等待原责任人操作即可完成取消、继续或接管流程。
- [ ] 非责任人直接调用 Agent API 时，服务端仍执行同样的责任人冲突校验。
- [ ] 客户端 A 不会收到自己的重复广播。
- [ ] 断线重连后客户端能补齐遗漏的实时版本。
- [ ] 两个客户端并发上报时，后到达版本最终生效；先到方先备份再被覆盖。
- [ ] 同一任务不同文件并发修改时两份修改都保留；同一文件并发修改时后到版本覆盖。
- [ ] 并发裁决结果写入审计，重复投递和乱序投递不能回退版本。
- [ ] Git 重新同步后，实时覆盖层与 Git 内容收敛且不会无故回退。

## Out of Scope

- 客户端新增服务端 Git 项目。
- 自动替用户 commit 或 push。
- 用实时上报替代 Git 的最终代码与任务内容一致性。
- 桌面登录与项目关联 UI；该部分属于 `11-08-desktop-account-login`。
