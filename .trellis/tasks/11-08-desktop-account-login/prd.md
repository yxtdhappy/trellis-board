# 桌面客户端账号密码直连登录

## Goal

把 Windows 桌面端现有的“设备令牌注册 + workspace 初始化”流程替换为单一登录页。用户双击客户端后直接看到“服务器地址 + 登录名 + 密码”，登录成功后进入当前账号有权访问的多团队 Board。

## Background

- 当前冷启动在存在 `client.json` 时直接加载 Board；不存在时加载本地注册页，并在注册后显示 workspace 初始化页：[main.rs](../../../desktop/src-tauri/src/main.rs:292)、[setup.js](../../../desktop/ui/setup.js:104)。
- 当前本地页要求“服务地址 + 设备名称 + 一次性设备令牌”，另有浏览器登录、配对码和 workspace 初始化入口：[index.html](../../../desktop/ui/index.html:16)、[setup.js](../../../desktop/ui/setup.js:141)。
- 当前 Web 端已经使用账号密码登录，并由服务端设置 HttpOnly Session Cookie：[LoginPage.tsx](../../../web/src/pages/login/LoginPage.tsx:74)、[http.js](../../../server/team/http.js:705)。
- `11-08-support-multi-team-board` 已确定登录不再选择活动团队，用户可访问团队由服务端实时成员关系决定；桌面设备凭证绑定“用户 + 设备”，不再绑定单一团队：[PRD](../archive/2026-11/11-08-support-multi-team-board/prd.md:17)、[design](../archive/2026-11/11-08-support-multi-team-board/design.md:31)。
- `11-08-support-multi-team-board` 明确把“移除设备令牌并改成账号密码直连 sidecar”留在任务外，因此本任务负责该交互调整，并依赖多团队认证契约先稳定。
- 当前首次注册后窗口的导航白名单没有动态加入 Board origin，导致登录后跳转可能被当作外链交给系统浏览器：[main.rs](../../../desktop/src-tauri/src/main.rs:345)、[navigation.rs](../../../desktop/src-tauri/src/navigation.rs:84)。
- 当前本地项目绑定只存在于 Agent CLI：`bind --project <ID> --path <仓库根目录> --branch <同步分支>`，桌面 GUI 没有关联入口：[cli.js](../../../agent/cli.js:63)、[cli.js](../../../agent/cli.js:300)。
- 服务端绑定过程已经校验项目访问权限、同步分支和 Git 远端身份；远端身份不一致时返回 `REMOTE_MISMATCH`：[agents.js](../../../server/team/agents.js:430)、[agents.js](../../../server/team/agents.js:512)。
- 当前绑定默认进入 `pending`，需要项目负责人审批后才能同步：[agents.js](../../../server/team/agents.js:561)、[agents.js](../../../server/team/agents.js:775)。

## Requirements

- 双击客户端后的默认页面始终是本地登录页，不再自动打开 Board，也不再显示设备令牌、设备名称、浏览器登录、配对码或 workspace 初始化入口。
- 登录页包含服务器地址、登录名、密码和登录按钮；服务器地址允许沿用上次成功值，密码不得持久化。
- workspace 初始化功能从桌面客户端完全删除；其后续实现方案在客户端核心能力具备后另行讨论。
- 登录由桌面端完成，密码只通过受控进程通信传递，不写入配置文件、WebView 存储、命令行参数或日志。
- 登录成功后，客户端应同时具备：
  - Board 可用的本地 WebView 会话；
  - 服务端签发的用户设备凭据，用于 sidecar 后续心跳和 Agent 授权。
- 登录成功后自动在客户端 WebView 内打开 Board，不调用系统浏览器。
- 服务端仍以实时团队成员关系决定可见团队和项目；客户端登录不得要求选择团队，也不得自行推断授权。
- 登录后客户端必须展示当前账号可见的团队项目，并允许用户选择服务端项目后关联一个本地 Git 仓库。
- 本地项目关联入口直接放在服务端 Board 的项目栏中，只对 Tauri 桌面客户端显示。
- 远程 Board 只获得项目关联所需的窄权限 Tauri 命令，不能获得文件系统、进程、Shell 或通用对话框权限。
- Rust 命令必须校验调用页面 origin 等于本次登录成功配置的 Board origin。
- 本地仓库必须是 Git 仓库根目录，当前分支必须等于服务端项目的同步分支，Git 远端必须与服务端项目远端一致；远端不一致时禁止关联。
- 客户端没有新增服务端项目的能力；项目只能先在服务端维护并启用，再出现在客户端的关联候选中。
- 账号只要属于目标启用团队，就拥有该团队全部启用项目的关联权限，不再要求项目负责人审批。
- 成员通过 Git 远端和分支强校验后，绑定直接进入可同步状态；桌面流程不出现待审批、批准或拒绝动作。
- 现有项目级 `read_only` 角色保留为例外：可关联并接收服务端内容，但禁止上传本地任务修改。
- 团队被禁用、成员被移出团队、项目停用、设备撤销或 Git 身份失效时，关联立即失效。
- 登录失败、服务端不可达、证书错误、账号禁用、首次登录需改密和已有设备冲突必须显示可操作的中文错误。
- 重新登录或切换账号时，应清理旧会话和旧设备绑定，避免 WebView 会话与 sidecar 凭据属于不同用户。
- 退出登录后回到本地登录页，并撤销当前会话、停止该设备的后台同步。
- 新逻辑不兼容现有已注册客户端：旧 `client.json`、旧设备令牌和旧 workspace 初始化页面不需要迁移或保留在线升级兼容。
- 新客户端首次登录时忽略并替换旧桌面配置；由新客户端自己生成的配置可在后续启动中用于预填服务器地址和复用同一账号的设备凭据。

## Acceptance Criteria

- [ ] 全新安装并双击客户端，只出现包含服务器地址、登录名和密码的登录页。
- [ ] 客户端代码和安装包中不再包含 workspace 初始化页面、目录选择入口或初始化 Tauri 命令。
- [ ] 输入错误密码时停留在登录页，密码被清空，不产生可用的 Board 会话或设备凭据。
- [ ] 输入正确密码后自动进入 Board WebView，当前窗口不跳转到系统浏览器。
- [ ] 账号属于多个团队时，登录不需要选择团队，Board 默认可看到全部授权团队数据。
- [ ] 登录后可以看到当前账号可访问的全部团队项目，并选择一个项目关联本地 Git 仓库。
- [ ] 桌面客户端在 Board 项目栏显示“关联本地项目”，普通浏览器不显示该入口。
- [ ] 非当前 Board origin 的其他远程页面调用关联命令被拒绝。
- [ ] 本地远端与所选服务端项目不一致时拒绝关联，并显示 `REMOTE_MISMATCH` 对应的中文错误。
- [ ] 本地当前分支与服务端项目同步分支不一致时拒绝关联。
- [ ] 客户端界面没有新增服务端项目的入口，桌面客户端也没有调用新增项目 API 的权限。
- [ ] 团队成员通过 Git 身份校验后直接进入可同步状态，不产生待审批记录或审批 UI。
- [ ] `read_only` 成员可以建立只读关联，但客户端明确显示只读状态且上传修改被服务端拒绝。
- [ ] 登录后的 sidecar 使用同一账号的设备凭据；设备凭据不包含固定活动团队。
- [ ] 登录成功后 `client.json` 不包含密码、Session Cookie 或设备明文凭据。
- [ ] 退出登录后 Board 会话失效，sidecar 后台同步停止，窗口回到本地登录页。
- [ ] 再次登录另一个账号时，不会复用前一个账号的 Session Cookie、设备凭据或团队缓存。
- [ ] 服务端断开、服务器地址非法或 TLS 失败时，客户端不打开 Board，并显示明确错误。
- [ ] 首次登录需要改密时，用户仍可进入 Board 完成改密；设备后台同步可在改密完成后的下一次登录建立。
- [ ] Windows 安装包冷启动验收通过，且本地页面只拥有登录所需的最小 Tauri IPC 权限。

## Out of Scope

- 现有已注册设备的在线迁移、向后兼容或静默升级。
- Web 浏览器登录页的多团队改造；该工作属于 `11-08-support-multi-team-board`。
- 管理员配对码和 Web 设备管理页面；是否保留为纯管理能力由后续任务决定。
- 密码找回、单点登录、OAuth、LDAP 或第三方身份源。
- 团队模式下客户端 `.trellis` 文件实时监听、变更上传、服务端多客户端汇总与实时广播；该能力需要独立任务设计和实施。
