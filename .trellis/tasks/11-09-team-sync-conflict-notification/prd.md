# 优化实时同步冲突覆盖提示

## Goal

当团队实时同步用服务端版本覆盖本地文件时，让用户准确知道影响了哪些任务、哪些文件、每个文件的来源版本，以及变化是实质内容还是仅换行格式，避免把普通补拉误认为多个任务丢失，降低误点“一键复原”的风险。

## Background

- 当前冲突判定位于 [live-sync.js](../../../agent/live-sync.js:924)，按原始文件字节的 SHA-256 比较，因此 `LF` 与 `CRLF` 不同也会被判定为冲突。
- 当前备份 manifest 的 [文件明细](../../../agent/live-sync.js:949) 只记录路径和摘要，未记录文件 revision、taskKey 和变化类型；[manifest 的任务列表](../../../agent/live-sync.js:962) 仍从本次拉取的全部文件计算，而不是从真实冲突文件计算。
- 当前控制事件已经从真实冲突文件生成 `taskKeys` 和文件路径，见 [live-sync.js](../../../agent/live-sync.js:1013)，但没有携带每个冲突文件的 `taskKey`、文件 revision 和变化类型。
- 当前控制窗口已经显示任务和文件，但仍使用完整 `taskKey`/路径，没有文件版本与变化类型，见 [control.js](../../../desktop/ui/control.js:92)。
- 已发生案例中，备份实际包含 3 个冲突文件、归属 2 个任务：一个 `task.json` 的 `status` 和 `branch` 发生变化，另外两个文件只有 `LF/CRLF` 差异；弹窗中的全局 revision 为 40，而三个文件最后变化 revision 分别为 25、25、38。
- 现有设计要求覆盖通知显示任务名称和路径，见 [team-realtime-task-sync/design.md](../11-08-team-realtime-task-sync/design.md:262)。

## Requirements

### R1 冲突归属准确

- `manifest.taskKeys` 必须只包含真实冲突文件对应的任务，不得包含本次拉取中内容未变化的其他任务。
- `remote_overwrite` 事件的 `taskKeys`、`fileCount` 和文件明细必须来自同一组真实冲突文件。
- 同一任务下多个冲突文件应合并为一个任务条目，不重复展示任务。

### R2 文件明细完整

- 每个冲突文件至少记录：
  - 相对路径；
  - `taskKey`；
  - 文件最后变化的 revision；
  - 本地与远端摘要；
  - 变化类型。
- 控制事件至少传递每个冲突文件的路径、`taskKey`、文件 revision 和变化类型。
- 全局 revision 保留为本次同步目标版本，但不能替代文件自身的 revision。
- 控制窗口使用任务目录名作为稳定标识，不为了显示标题额外读取工作区文件。

### R3 覆盖提示可识别

- 控制窗口必须显示涉及的冲突任务，以及每个任务下的冲突文件，而不是只显示文件数和备份路径。
- 控制窗口必须先给出“2 个任务、3 个文件”的摘要，再显示每个文件的路径、文件版本和变化类型；长内容必须能够换行。
- 实质内容变化与仅换行差异必须使用不同文案或状态标识。
- “一键复原”必须明确表示会恢复本次全部冲突文件、生成新的团队版本并广播给其他客户端。

### R4 换行差异识别

- 当本地与远端文本除 `LF` 与 `CRLF` 外完全一致时，标记为“仅换行差异”。
- 清理换行差异不能改变冲突覆盖和备份的安全策略；文件仍按现有顺序先备份再覆盖。
- 其他空白、字符或字段变化不得误判为“仅换行差异”。

### R5 兼容与范围

- 不改变现有冲突解决策略：仍以服务端实时内容覆盖本地。
- 不自动点击、自动执行或取消一键复原。
- 不增加三方合并、可视化 diff、冲突编辑器或保留多版本历史。
- 旧备份 manifest 缺少新增字段时，控制窗口必须降级显示，不能报错。

## Acceptance Criteria

- [x] 拉取结果同时包含冲突文件和非冲突文件时，`manifest.taskKeys` 与 `remote_overwrite.taskKeys` 只包含真实冲突任务。
- [x] 同一批 3 个冲突文件分属 2 个任务时，事件明确给出 2 个任务、3 个文件，且每个文件包含路径、taskKey、文件 revision 和变化类型。
- [x] 两个文本仅 `LF/CRLF` 不同时，事件将其标记为“仅换行差异”；其他内容变化标记为实质变化。
- [x] 控制窗口先显示任务数和文件数，再显示任务目录名以及每个文件的路径、版本和变化类型。
- [x] 控制窗口同时说明全局同步版本和文件自身版本，不再让用户把全局 revision 理解为每个文件的修改版本。
- [x] 一键复原文案明确说明会恢复全部冲突文件、形成新团队版本并广播。
- [x] 旧 manifest 或缺少 revision、变化类型的事件仍能降级显示。
- [x] 新增自动化测试覆盖冲突任务去重、非冲突任务排除、仅换行差异识别和事件字段。
- [x] 相关 Agent 测试和桌面脚本语法检查通过。
- [ ] 真实 Tauri 控制窗口壳层验证通过。

## Out of Scope

- 自动恢复或自动删除任何现有备份。
- 修改服务端冲突判定、revision 分配或实时同步协议。
- 自动合并本地与远端文本。
- 在任务卡片或看板中展示完整冲突文件历史。
