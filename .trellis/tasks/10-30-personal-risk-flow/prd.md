# 个人执行：风险与流动

## Goal

让个人用户能及时看到被什么阻断、哪些任务解除阻断后可以立即推进，以及当前并行工作是否已经超出自己的承载能力。

## Dependencies

- 必须先完成并归档 `10-30-personal-plan-attention`。
- 依赖其 SQLite 稳定任务身份、事件表、board 执行投影和计划字段。
- 本任务把数据库从 schema v2 顺序迁移到 v3。
- 依赖顺序只记录在本文档和执行计划中，不把父子树位置当作依赖。

## Requirements

- R1 新增独立于父子关系的 `blocked by` / `blocks` 依赖模型。
- R2 每条活动依赖包含阻断方、被阻断方、原因、创建人、创建时间和解除时间。
- R3 用户可从任务详情创建和解除依赖；被阻断任务的 `blocks` 视图由反向查询生成。
- R4 拒绝缺失任务、自引用、重复活动依赖和任意长度的循环依赖。
- R5 创建或解除依赖失败时，不得留下依赖、事件或投影的部分写入。
- R6 提供“当前被阻断”队列和“解除阻断后可推进”队列；阻断时长由事件区间计算。
- R7 实现中任务支持个人软性 WIP 上限，默认 2，达到或超过上限时显示提醒但不阻止操作。
- R8 DoR 缺失项根据 PRD、Design、Implement plan 和规划评审证据提示。
- R9 DoD 缺失项根据实施、检查、验收项、工作提交和归档证据提示。
- R10 DoR/DoD 缺口仅为建议，不阻止启动、检查、归档或人工阶段确认。
- R11 风险状态必须能解释原因，不能只靠颜色或单个汇总分表达。
- R12 在现有自定义视图上增加 `blocked / unblocked / any` 条件，已有保存视图保持兼容。

## Acceptance Criteria

- [ ] 创建合法依赖后，阻断方显示 `blocks`，被阻断方显示 `blocked by` 和原因。
- [ ] 自引用、缺失任务、重复活动和 A→B→A 循环均在写入前被拒绝。
- [ ] 任一步依赖写失败后，数据库没有新增依赖或事件。
- [ ] 解除依赖后活动队列立即移除，历史记录保留创建与解除时间。
- [ ] 阻断时长按创建和解除事件计算；重新打开服务和页面后结果一致。
- [ ] “解除阻断后可推进”队列只包含当前无其他活动阻断的任务。
- [ ] WIP 达到或超过上限时仍可确认阶段；提醒文案明确是软限制。
- [ ] DoR/DoD 缺口列出具体缺失项，不改变现有按钮可用性。
- [ ] 保存视图可选择阻断状态；旧保存视图缺少该字段时继续正常工作。
- [ ] 计划、标签、保存视图、人工阶段和归档任务可继续正常使用。
- [ ] `npm test`、JavaScript 语法检查、真实 API 验证和浏览器页面验收通过。

## Out of Scope

- 自动排期、关键路径计算和阻断 SLA。
- 阻止用户启动或归档任务。
- 跨主机 Agent、通知推送和团队权限。
- 操作撤销和完整周期指标。

## Product Decisions

- 软 WIP 默认实现中 2 项，用户可以明确忽略提醒。
- DoR/DoD 是决策辅助，不是流程门禁。
- 父子任务与阻断依赖必须同时可见，但语义和数据结构分离。
