# 规范初始化设计

## 文档结构

- `backend/` 描述 `server/` 的运行时、模块依赖、SQLite、扫描和 HTTP 边界。
- `frontend/` 描述 `public/` 的原生 DOM、全局状态、渲染和轮询模式。
- `guides/` 只放跨层思考检查，不复制具体代码契约。

## 编写原则

- 每项规则必须能追溯到当前源码、配置、测试或命令输出。
- 已知技术债明确记录，不在文档任务中顺手修改产品代码。
- 规范说明“下一处代码应如何安全实现”，而不是复述通用最佳实践。
- 代码行为变化时应同步对应规范，并让层索引保持可达。

## 验收边界

- 文档结构、链接和当前技术事实一致。
- 产品源代码、测试和运行行为不变。
- E2E 不是本任务的必需证据；规范和静态检查足以验证交付。
