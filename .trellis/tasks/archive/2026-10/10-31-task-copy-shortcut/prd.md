# 列表与详情增加接取任务复制入口

## Goal

让用户在看板任务卡片或任务详情中一键复制精确的任务目录名，直接用于在 Agent 中定位并打开对应任务。

## Background

- 截图中的目标值是任务目录名，例如 `10-31-FIX-PUBLISH-ORDER-BY-COMPOSITE-PRIMARY`，不是任务的中文标题。
- `/api/board` 与 `/api/task` 已返回 `dirName`，该字段就是任务目录 basename，因此不需要新增或修改接口。
- 当前主看板任务卡片已有整卡透明点击层和“计划”按钮；复制按钮必须独立响应，不能顺带打开任务详情。

## Requirements

### R1：看板卡片提供显眼入口

主看板任务卡片显示“复制任务名”按钮，视觉上明显高于普通辅助文字，同时不能破坏标题、阶段进度、负责人、计划按钮和整卡打开详情行为。

### R2：任务详情提供同等入口

任务详情标题区域显示“复制任务名”按钮，用户打开任一活动或归档任务后都能复制当前任务目录名。

### R3：复制内容精确且可验证

两个入口都复制当前任务的 `dirName` 原值：

- 不加日期、项目名、仓库路径或 `.trellis/tasks/` 前缀。
- 不复制中文 `title`，也不复制复合标识 `taskKey`。

### R4：复制结果有明确反馈

- 复制成功后按钮短暂显示“已复制”，并通过可被辅助技术感知的状态文案说明已复制的是哪个任务目录名。
- Clipboard API 不可用或被拒绝时，使用可在当前页面执行的降级复制方式。
- 降级仍失败时显示中文错误，不静默失败。

### R5：交互和布局可用

- 鼠标、键盘 Tab、Enter 和 Space 都能触发复制。
- 点击卡片中的“复制任务名”不会打开任务详情。
- 860px 以下视口不产生横向溢出，详情标题区的复制按钮和关闭按钮仍可见。

## Acceptance Criteria

- [x] 主看板每个任务卡片的“复制任务名”点击后，剪贴板内容严格等于该任务的 `dirName`。
- [x] 任务详情标题区的“复制任务名”点击后，剪贴板内容严格等于当前任务的 `dirName`。
- [x] 复制成功后按钮出现“已复制”反馈，页面和按钮状态可恢复，不导致整卡详情误打开。
- [x] Clipboard API 成功路径和失败降级路径均可验证；彻底失败时显示中文错误。
- [x] 活动任务和归档任务在详情中都可执行复制。
- [x] Tab、Enter、Space 可完成复制，`:focus-visible` 清晰可见。
- [x] 860px 以下列表、详情标题区和底部操作区无横向溢出。
- [x] 浏览器控制台和网络请求没有因本改动新增错误。

## Out of Scope

- 不新增真实的“接取/认领并启动 Agent”后端操作。
- 不修改任务目录名、任务标题或 `task.json`。
- 不增加批量复制、复制项目路径或在列表中重复展示完整目录名。
- 不新增接口、数据库字段、前端框架或构建链。

## Technical Notes

- 轻量任务，保持 PRD-only。
- 页面渲染仍使用现有 `renderX()` / `bindX()` 模板和事件绑定模式。
- 复用现有按钮与设计 token，不引入组件库。
- UI 改动除 Node 自动测试外，必须使用真实浏览器验证复制值、反馈、键盘操作和响应式布局。
