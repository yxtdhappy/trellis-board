# 个人版执行增强：集成实施计划

## 执行原则

- 父任务不直接实现功能；按三个子任务顺序启动、实现、检查、提交和归档。
- 每个子任务都从 `prd.md`、`design.md`、`implement.md` 和已登记上下文开始。
- 当前仓库没有构建和 lint 脚本。开发过程中只做必要的局部验证；全部代码完成后统一执行一次 `npm test`、JavaScript 语法检查和真实浏览器验收。
- 每个写操作先验证无效输入和事务回滚，再做成功路径。

## 子任务顺序

### 1. `10-30-personal-plan-attention`

交付：

- SQLite v2 迁移、稳定执行身份、计划字段、标签、保存视图。
- 事件基线、人工阶段事件和扫描阶段观察。
- 推荐任务、注意力队列、快速编辑和首屏信息层级。

完成门槛：

- 计划字段和视图重启后保留。
- 目标仓库 `task.json` 未被扩展字段污染。
- 事件明确来源且不包含迁移前伪造历史。
- 测试、语法检查、真实 API 和浏览器 E2E 通过。

归档后才能启动风险子任务。

### 2. `10-30-personal-risk-flow`

交付：

- SQLite v3 的 `task_dependency`。
- `blocked by`/`blocks`、阻断原因与时长、解除阻断队列。
- 软 WIP 上限和 DoR/DoD 缺失提醒。

完成门槛：

- 缺失、自引用、重复、循环依赖均被拒绝且无部分写入。
- 风险提醒不改变原有阶段操作可用性。
- 前端可创建和解除依赖，刷新后状态一致。
- 测试、语法检查、真实 API 和浏览器 E2E 通过。

归档后才能启动追溯子任务。

### 3. `10-30-personal-history-insights`

交付：

- 任务事件时间线、最近一次可逆操作撤销。
- 追踪后的 Lead/Cycle、阶段停留、回流、阻断占比。
- `missing`/`partial`/`tracked` 完整度和缺失说明。

完成门槛：

- 撤销追加补偿事件，不删除原历史。
- 刷新和重启后撤销结果与事件顺序稳定。
- 相同事件集重复计算结果一致。
- 证据不足时不输出猜测数字。
- 测试、语法检查、真实 API 和浏览器 E2E 通过。

## 验证命令

所有实现完成后统一执行：

```powershell
npm test
Get-ChildItem server,public,tests -Filter *.js -Recurse | ForEach-Object { node --check $_.FullName }
node server/index.js
```

真实服务验收至少覆盖：

1. 启动、扫描缓存加载和 `/api/health`。
2. 计划字段写入、重启持久化、`task.json` 未变化。
3. 保存视图创建、组合筛选、删除。
4. 依赖创建、解除、循环拒绝、阻断时长。
5. 事件时间线、撤销、指标缺失与 partial 状态。
6. 任务列表、详情、团队、归档、项目管理和任务创建回归。
7. 1440px 桌面和 860px 以下响应式；键盘焦点、对话框关闭和控制台错误。

## 高风险文件与回滚点

- `server/database.js`：迁移失败会阻止启动；任何 schema 改写前备份 `data/board.sqlite*`。
- `server/loader.js`：稳定身份和列表投影影响所有视图；字段名变更需一次改完全部消费者。
- `server/index.js`：路由和组合投影影响 board/detail；每次接口改动都做真实 HTTP 验证。
- `public/app.js`：动态 `innerHTML` 后必须重新绑定事件；所有服务端文本经 `safe()`。
- `public/styles.css`：保留现有断点和 reduced-motion，不引入第二份全局设计系统。

每个子任务提交前保留可回滚边界：schema 迁移单独提交，领域写入单独提交，UI 和集成单独提交。不得在未确认代码分组前使用破坏性 Git 命令。
