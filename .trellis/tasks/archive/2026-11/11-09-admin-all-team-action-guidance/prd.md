# 优化全部团队范围下的项目接入与设备撤销

## Goal

让系统管理员在“全部团队”范围下可以完成安全的设备撤销，并在不能直接执行的项目接入动作前看到明确的团队选择引导；同时清理已经过期的桌面设备接入提示。

## Background

- 系统管理员进入管理台时默认选中“全部团队”。`web/src/hooks/useAdminConsole.ts:122` 将初始范围设为 `all`。
- “识别远端”在 `web/src/features/admin/OnboardingTab.tsx:261` 因 `adminTeamId === 'all'` 而禁用，但页面没有就地解释。浏览器复现确认：URL 已填写时按钮仍禁用，切换具体团队后立即恢复。
- 项目接入后端要求明确的目标团队。`server/team/teams.js:421` 在系统管理员未传团队时返回“请先选择目标团队”，因此不能把一个项目接入请求静默归到任意团队。
- 设备列表允许系统管理员查看全部团队设备。`server/team/agents.js:882` 至 `server/team/agents.js:961` 已支持系统管理员在未指定团队时执行全局撤销；当前 `web/src/hooks/useAdminConsole.ts:277` 在发起请求前直接拦截了 `all`，导致可用能力被前端误禁。
- 桌面客户端登录会自动复用有效设备，或在同一次登录流程中签发一次性兑换令牌并创建设备；详见 `desktop/sidecar/desktop-device.js:373` 和 `desktop/README.md:15`。
- 当前安装脚本已不再注册 `trellisboard://` 深链，详见 `desktop/README.md:217`；但 Agent 设备页仍展示“桌面客户端登录接力”和深链按钮，属于过期入口。
- 配对码仍被源码 Agent CLI 的 `pair` 命令使用，且“项目协作”页已有“生成我的配对码”入口。Agent 设备页中的重复面板不是桌面客户端登录所必需，但后端配对能力仍需保留。

## Proposed Requirements

1. 在“全部团队”范围进入项目接入时，页面必须明确提示项目接入需要具体团队。
2. 若当前账号只有一个可管理团队，项目接入可直接使用该团队，避免无意义的额外选择；存在多个可管理团队时仍要求用户显式选择，不能自动选择任意团队。
3. 系统管理员在“全部团队”范围撤销设备时，二次确认文案必须明确说明撤销范围是全部团队；确认后应成功撤销设备、全部团队绑定和待执行命令。
4. 非系统管理员仍不能在“全部团队”范围执行跨团队设备撤销；必须要求选择其有权管理的具体团队。
5. 从 Agent 设备页移除已经过期的“桌面客户端登录接力”卡片。
6. 保留“管理员兜底：生成配对码”卡片，并改名为面向源码或命令行 Agent 的入口；不删除配对码接口、Agent CLI 配对流程和“项目协作”页入口。

## Acceptance Criteria

- [ ] 系统管理员仅有一个可管理团队时，在“全部团队”进入项目接入可直接识别远端，或页面自动切换到该团队且明确显示当前目标团队。
- [ ] 系统管理员有多个可管理团队且仍选中“全部团队”时，项目接入表单显示明确的团队选择提示，“识别远端”不可用原因可见。
- [ ] 系统管理员在“全部团队”点击撤销设备，确认文案说明全局影响，确认后设备状态变为 `revoked`，相关绑定和待执行命令失效。
- [ ] 非系统管理员在“全部团队”尝试撤销设备时仍收到选择具体团队的提示，服务端权限边界不变。
- [ ] Agent 设备页不再显示桌面客户端登录令牌和已失效的深链按钮。
- [ ] Agent 设备页仍可生成配对码，并将入口语义明确为命令行 Agent 兜底。
- [ ] 项目协作页仍可生成配对码，Agent CLI 配对流程与相关测试保持通过。

## Out of Scope

- 不移除桌面登录自动创建设备的服务端流程。
- 不移除 Agent CLI、配对码接口或已有数据库表。
- 不改变项目接入、设备撤销和团队隔离的后端权限规则；系统管理员全局撤销复用现有接口。

## Technical Notes

- 项目接入页在“全部团队”且仅有一个可管理团队时，进入页面后自动切换到该团队；存在多个团队时继续保留“全部团队”并显示明确的选择提示。
- 系统管理员在“全部团队”撤销设备时向前端 API 传空团队范围，服务端按现有全局撤销语义处理；团队管理员仍要求具体团队。
- 删除 Agent 设备页不再使用的桌面登录令牌状态、API 包装和深链入口；服务端 `/api/desktop/enroll-tokens` 保持供桌面客户端内部使用。
- 该任务按轻量任务处理，`prd.md` 作为规划和验收依据；实现与检查通过 Trellis 子代理完成。
