# 切换服务器地址时备份并清理客户端数据

## Goal

桌面客户端在「退出后重新登录」时，如果用户把服务器地址改成了与上次不同的地址，登录前必须二次确认；用户确认后，先备份旧服务器的登录数据与项目绑定数据，再清理本地旧数据，然后用新地址登录。首次登录和地址未变化时不做任何提醒。

## Background

- 退出登录只清除 `client.json` 里的密码，保留 `server_url` 和 `username`（`packages/desktop/src-tauri/src/main.rs:270`），所以重新登录时地址会预填，用户可直接改成另一个服务器并提交。
- 现有 `desktop_login` 里已有 `force_new`（`main.rs:441`），它只决定「新建还是复用设备会话」，不清理旧服务器遗留的本机数据：旧设备凭证、旧项目绑定、旧同步游标、旧插件配置会和新服务器数据混在同一个 data 目录里。
- 客户端 data 目录 `%LOCALAPPDATA%\TrellisBoard\data`（`packages/desktop/src-tauri/src/config.rs:27`）同时存放运行环境（便携 Node、Trellis CLI、kit 资源、Python 安装包）、更新包、外观设置、桌面日志，以及登录/绑定数据。清理必须精确，不能连带删掉运行环境。

## Requirements

### R1 触发条件

- 本地存在上次登录的服务器地址（即非首次登录）。
- 本次提交的服务器地址经与服务端一致的归一化后，与上次记录的地址不同。
- 归一化规则复用现有 Board 地址归一化（协议 + 主机 + 端口 + 子路径，去掉尾部 `/`，主机名大小写不敏感，默认端口视为相同）；仅差异在尾部斜杠、大小写、默认端口时不触发。
- 首次登录（无记录）不提醒。

### R2 提醒内容与交互

- 提醒必须明显说明：更换服务器地址会清除旧服务器的登录数据与项目绑定数据。
- 提醒中显示「原地址 → 新地址」，提供「取消」和「确认切换」两个动作。
- 取消：不发起登录请求、不改动任何本地文件，停留在登录页，用户可继续修改地址后重新提交。

### R3 确认后的清理

- 顺序固定为：备份 → 删除 → 登录。备份失败必须中止登录且不删除任何数据。
- 清理范围（登录数据与项目绑定数据）：
  - 登录配置（含服务器地址、登录名、密码、设备会话凭证）；
  - Agent 数据目录（设备凭证、项目绑定、同步游标、控制状态、hooks、Agent 日志）；
  - 按「服务器 + 用户」隔离的桌面插件数据。
- 保留范围：运行环境（便携 Node、Trellis CLI、kit 资源、Python 安装包）、npm 全局目录、更新包与更新状态、用户本地安装的插件目录、外观设置、桌面客户端日志。

### R4 备份

- 备份目录与 data 目录同级，命名 `data-backup-<yyyyMMdd-HHmmss>`（本地时间）。
- 备份内容与 R3 清理范围一致，保持相对路径结构。
- 自动保留最近 3 份 `data-backup-*`，更旧的自动删除。
- 备份失败（磁盘不足、目标不可写、复制中断）时：清理备份残留，保留原数据，登录中止并给出可见错误。

### R5 登录失败的处理

- 清理后若登录失败（地址不可达、密码错误、服务端拒绝），必须用备份恢复被清理的旧数据，并在登录页提示「已恢复原服务器数据」，避免用户在未成功切换时丢掉旧服务器登录能力。
- 恢复失败时提示备份目录路径，便于人工恢复；日志记录失败原因。

### R6 运行环境连续性

- 清理后不要求用户重新安装运行环境；下次 `runtime_status` 检查应保持就绪，不触发 Node/Trellis 重新下载。

### R7 作用域与安全

- 该保护只在桌面客户端本地登录页生效；浏览器直接访问 Board 不受影响。
- 新增命令只对本地登录页开放，不对远程 Board 开放。
- 日志中不得出现密码、令牌、设备凭证明文（沿用现有脱敏）。

## Non-goals

- 不做多服务器数据并存或多套配置切换。
- 不清理旧服务器的服务端会话（退出登录时已尽力撤销）。
- 不删除本地已 clone 的项目仓库和 git worktree。
- 不改变首次登录、地址未变化登录、自动登录的既有行为。

## Acceptance Criteria

- [ ] 无上次地址记录（首次登录）→ 直接登录，无确认弹窗。
- [ ] 提交地址与上次相同（仅尾部 `/`、大小写、默认端口差异）→ 直接登录，无确认弹窗。
- [ ] 提交地址变为另一个服务器 → 出现确认弹窗，文案明确包含「清除旧服务器的登录数据与项目绑定数据」，并显示原地址与新地址。
- [ ] 弹窗取消 → 不调用登录命令、data 目录内容不变、仍在登录页。
- [ ] 弹窗确认且登录成功 → 生成 `data-backup-*` 备份目录（含登录配置、Agent 数据、插件数据），旧数据被移除，新服务器登录成功。
- [ ] 备份失败（目标目录不可写）→ 登录中止、旧数据完整保留、页面显示错误。
- [ ] 清理后登录失败 → 旧数据被恢复，登录页提示已恢复，备份目录仍保留。
- [ ] 连续切换 4 次后，`data-backup-*` 目录只剩最近 3 份。
- [ ] 切换完成后 `runtime_status` 仍为 ready（`node_runtime` / `trellis_runtime` 标记保留），不触发下载。
- [ ] 清理保留了 `runtime/`、`npm-global/`、`updates/`、`plugins/`、`appearance.json`、`logs/`。
- [ ] 备份与清理日志中无密码、令牌明文。
- [ ] 远程 Board 页面无法调用新增命令（capability 未授权）。
