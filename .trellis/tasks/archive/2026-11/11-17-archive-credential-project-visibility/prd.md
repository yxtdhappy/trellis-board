# 归档同步凭据与项目关联展示优化

## Goal

让管理员在“归档同步”页面直接看出每个来源凭据会影响哪些项目、每个项目实际匹配到哪个凭据，以及删除凭据会影响哪些项目。保留现有按 `scheme + host + port` 自动匹配凭据的模型，不引入逐项目绑定。

## Background / 已确认事实

- 凭据严格按协议、主机和端口隔离；来源相同的项目会隐式复用同一凭据。
- 归档同步接口已经为每个任务空间返回匹配到的凭据对象，前端无需新增数据库字段或认证接口。
- 当前凭据卡片只显示名称、来源和主机指纹，没有显示适用项目数量或项目列表。
- 当前项目行只显示“凭据已配置”等状态，没有显示实际使用的凭据名称；该文案也不代表 SSH/HTTPS 认证已经成功。
- 项目名称、分支名称、来源、同步状态和匹配凭据都已在现有接口数据中提供。
- 当前截图中的“任务文件类型不受支持”属于同步或导入阶段错误，不应被展示成凭据匹配错误。

## Requirements

### R1 凭据卡片展示自动适用项目

- R1.1 每张凭据卡片显示自动适用的项目数量，例如“自动适用 3 个项目”。
- R1.2 支持展开查看项目名称和分支，例如“mdp-backend-service · dev”。
- R1.3 没有适用项目时明确显示“当前没有项目使用此来源”，不能留空。
- R1.4 项目数量较多时提供折叠或限制展示，避免管理页被单张凭据撑得过长。

### R2 项目行展示实际匹配的凭据

- R2.1 `configured` 状态显示实际凭据名称，例如“使用凭据：公司 GitLab 只读凭据”。
- R2.2 将“已配置”调整为能表达匹配语义的文案，例如“已匹配”；没有认证测试结果时显示“未验证”，不能暗示认证已经成功。
- R2.3 `anonymous`、`missing`、`unsupported` 继续显示各自明确的中文状态，不显示虚假的凭据名称。
- R2.4 页面不得展示私钥、Token 或其他秘密内容；可以继续展示现有的公开指纹信息。

### R3 删除凭据前展示影响范围

- R3.1 删除凭据的确认框显示受影响项目数量。
- R3.2 确认框至少列出受影响项目的名称和分支，让管理员在删除前能够判断影响范围。
- R3.3 项目较多时允许折叠或限制条目，但必须保留总数，不能隐藏“还会影响其他项目”的事实。
- R3.4 删除操作仍然调用现有删除接口，不改变凭据删除语义。

### R4 保持一致性和可访问性

- R4.1 关联项目必须使用接口返回的项目和凭据数据计算，不在前端推测主机或端口是否相同。
- R4.2 展开、折叠表单和删除确认应支持键盘操作，并有清晰的可访问名称。
- R4.3 名称缺失或接口返回异常数据时使用可识别的降级文案，不能让页面崩溃。

## Acceptance Criteria

- [ ] 凭据卡片能显示适用项目数量和项目的“名称 + 分支”；点击后可查看关联项目。
- [ ] 截图中的“公司 GitLab 只读凭据”能明确显示适用于 `ssh://git.weintdata.cn:1022` 下的三个项目，而不是要求用户自行对照来源地址。
- [ ] 项目行能显示实际匹配的凭据名称；`configured` 不再被表达成“认证成功”。
- [ ] `missing`、`anonymous`、`unsupported` 状态仍能正确显示，不会错误显示其他凭据。
- [ ] 删除凭据的确认框会列出受影响项目数量和项目/分支信息。
- [ ] 适用项目为空时有明确空状态，项目较多时页面仍可正常滚动和阅读。
- [ ] 不修改凭据匹配规则、认证流程、归档同步流程或数据库结构。
- [ ] 页面刷新、只读接口数据和现有同步错误展示行为不受影响。

## Out of Scope

- 不增加“一个项目单独覆盖一个凭据”的能力。
- 不新增凭据测试历史、认证成功状态或后端状态字段。
- 不处理“任务文件类型不受支持”等归档文件校验和 Git 同步错误。
- 不改动归档任务同步、服务端 Git 拉取或客户端同步逻辑。
- 不展示或导出任何秘密、私钥、Token 或主机登录凭据。
