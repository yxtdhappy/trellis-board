# 按 CPU 热点优化状态刷新实施计划

## 0. 前置

- 先完成任务 `11-14-deferred-status-reconcile`。两个任务都会修改
  `apps/desktop/src-tauri/src/agent/task_sync.rs`。
- 本任务必须复用该任务已经建立的 `write_cursor` 实际变化判定，只在该分支增加状态通知。
- 不在 deferred 收敛尚未稳定时并行修改同一 Rust 同步层。

## 1. 基线与归因

- 使用同一可执行文件、同一账号、同一组本地关联和相同页面状态记录空闲 CPU。
- 至少采集 Board 与归档各 30 秒；条件允许时延长到 10 分钟。
- 记录 `trellis-board-client` 及其 WebView 子进程的平均 CPU、P95、峰值。
- 统计 `/api/team/status`、`/api/task-operations`、`list_local_associations`、
  `desktop_sidecar_status` 和 `live_control_pending` 的调用频率。
- 检查 CPU 尖峰与固定间隔是否相关；无请求间隔变化时不得把尖峰归因给轮询。
- 保存基线数据和候选路径排序后再改产品代码。
- 只对本地关联、控制窗口和条件性的 Team 状态做事件化归因；Agent 与协议周期任务不进入候选范围。

当前已采集的组合基线：v0.4.9 真实客户端 PID `21548` 的进程树
`21548,56308,41532,63904,67004,48784,30008` 连续 30 秒 CPU 时间增量 `2.0s`，即单核 `6.67%`；
根进程工作集约 `125MB`，五条关联均显示“已关联 · 同步正常”。该数据没有逐路径归因，不能据此
增加 Team 状态 SSE。

## 2. 本地关联事件

- 在 Rust 侧建立统一、可合并的桌面状态通知。
- 只在 cursor、binding、deferred、ownership 或 sidecar 状态实际变化时发射。
- 补充本地 Git HEAD/ref/index 监听，避免外部 Git 合并后 ProjectRail 直到 focus 才更新。
- ProjectRail 先注册监听再首次读取，并把事件刷新接入单一在途请求保护。
- 相等结果复用现有状态引用，避免父组件重复渲染。
- 页面可见时保留 10 秒兜底 timer；页面隐藏时停止，恢复可见或聚焦时立即刷新。

验证：

- Rust 单测覆盖无变化不发射、实际变化发射、多个变化合并。
- 前端测试覆盖事件刷新、在途请求合并和相同结果不重绘。
- 真实客户端 attach/detach/同步/deferred 清理后不依赖 3 秒定时器即可更新。

## 3. 控制窗口事件

- ControlHub 每次队列内容实际变化后通知控制窗口。
- ControlApp 改为监听后首次读取，不再每 750 毫秒请求。
- 保留 JSON 签名相等判断，避免重复渲染。
- 可见窗口保留 10 秒兜底；隐藏窗口停止 timer，恢复显示时立即刷新。

验证：

- 无待处理事件时 30 秒内不调用 `live_control_pending`。
- 新增、替换、dismiss 和连续队列推进都能立即显示正确事件。
- 窗口关闭、重建和监听注册竞态由首次读取补齐。

## 4. Team 状态条件优化

无论基线结果，都把 `/api/team/status` 改为 ETag 条件请求和 10 秒可见兜底。只有基线证明它仍是
显著热点时，才继续执行 SSE 事件化。

- Board SSE 增加 `team.status.changed`，按短窗口合并。
- 只在 listener、binding、项目可见性、taskSpace 或 pending assignment 投影变化时发射。
- Agent 心跳本身不直接触发浏览器刷新。
- 前端使用 ETag 条件请求，`304` 不更新状态。
- focus、visible 和 SSE 重连仍执行一次条件请求。
- 页面隐藏时停止 10 秒 timer；恢复可见时立即条件请求并重新调度。

验证：

- 无状态变化时，可见页面每 10 秒最多一次条件请求，未变化响应为 304；隐藏页面不请求。
- 在线/离线、关联状态和 pending assignment 变化各触发一次请求。
- 相同 Team 状态返回 `304` 时不重绘。
- SSE 断开期间发生的变化在重连后补齐。

## 5. 低成本路径处理

- 创建/改派详情查询只在 `pending/delivered/running` 时继续；`failed/succeeded/cancelled` 到达终态
  后停止，用户点击重试时重新启动。
- 任务操作列表只在选中具体 taskSpace 时创建 3 秒定时器；结果不变时保留原数组。
- sidecar、插件页和接入推送检查保持原行为。
- 若实现过程中已有事件通道可以零成本覆盖 sidecar，可顺带接入；不得为此新增独立协议。
- 只对实际出现重复渲染的路径增加结果相等保护，不扩大为架构改造。

## 5.1 明确不改范围

- 不新增 Agent、SSE 心跳、命令补偿、插件健康检查、插件定时器或备份相关 SSE。
- 不为插件页和接入推送检查新建状态事件。
- 不为创建/改派进度新增 `task.operations.changed` SSE；保留短时退避查询。

## 6. 最终验证

- 所有开发完成后，仅执行一次最终编译/类型检查和必要测试，不在每个小步骤重复构建。
- 运行现有自动化测试，覆盖任务同步、ownership、deferred、冲突、分支门禁和 SSE。
- 在真实 Windows 客户端执行 Board、归档、本地关联、控制窗口、重连和 focus 恢复。
- 重新采集最终 CPU，与基线比较平均、P95、峰值和请求次数。
- 任一优化项无 CPU 收益或稳定性下降时回退该项，不通过继续扩大事件化范围补偿。

## 7. 风险点与回退

- Rust 通知发射点必须只在真实变化后调用，避免以更快的频率重复原问题。
- 事件合并和请求在途保护必须保留最后一条 pending refresh，不能丢最终状态。
- 本地 Git 监听失败时，focus/visibility 一次性刷新仍必须工作。
- 各路径独立提交式回退：关联、控制窗口、Team 状态互不依赖。
