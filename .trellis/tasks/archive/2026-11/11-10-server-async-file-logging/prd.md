# 服务端日志异步落盘

## Goal

让 Trellis Board 服务端在终端关闭后仍保留运行日志。日志写入磁盘的过程不得同步阻塞 HTTP 请求、文件扫描或 Agent 事件处理。

## Background

- 当前服务端主要使用 `console.log/warn/error` 输出，启动和运行日志只存在于启动终端；默认数据目录 `%LOCALAPPDATA%\TrellisBoard\server` 中没有服务端日志文件。
- standalone、team 模式和插件宿主都通过 `console` 记录服务端日志。
- 现有 `agent/logger.js` 已实现异步缓冲写入、大小轮转、敏感信息脱敏和关闭前 flush，可作为实现参考。
- 当前工作区存在其他未提交改动；本任务不得覆盖或夹带这些改动。

## Requirements

- 服务端启动后，将主进程日志以 UTF-8 追加写入运行数据目录下的 `logs/server.log`。
- 同时保留控制台输出，不改变现有开发、运维观察方式。
- 文件写入必须异步执行，不得在日志调用点等待磁盘 I/O。
- 日志写入失败不得导致服务退出或阻塞业务请求；应降级为仅控制台输出。
- 在正常收到 `SIGINT` 或 `SIGTERM` 时，先停止服务，再刷新并关闭日志写入资源。
- 对 Bearer、URL 用户信息、密码、配对码、设备凭证、令牌和 Windows 本地绝对路径进行脱敏后再写文件。
- 日志文件按 `5 MiB × 5` 轮转：当前文件加 4 个历史文件，总占用上限约 25 MiB。
- 保持 standalone 与 team 模式行为一致，不修改插件自身已有的日志文件机制。

## Acceptance Criteria

- [x] 启动服务后，`server.log` 出现在运行数据目录的 `logs/` 下，并包含启动信息。
- [x] 触发一次服务端请求或后台任务日志后，无需关闭服务即可在日志文件中看到对应记录。
- [x] 日志写入不会阻塞 HTTP 请求；文件写入失败时服务继续响应。
- [x] 含敏感信息或本地绝对路径的日志写入文件时已脱敏，控制台行为保持兼容。
- [x] 达到轮转阈值后，当前日志被轮转，历史文件数量不超过配置上限。
- [x] 正常关闭服务后，最后一批已进入内存缓冲的日志已写入文件。
- [x] 自动化测试覆盖异步缓冲、轮转、脱敏、写入失败降级和正常关闭 flush。
- [x] standalone 和 team 模式均完成真实启动验证。

## Out of Scope

- 集中式日志服务、日志上传、HTTP 日志查询页或 UI。
- 断电、蓝屏或强制终止条件下的零丢失保证。
- 为每条日志执行同步 `fsync` 或替代现有审计表。
- 修改插件子进程自身的日志落盘与轮转规则。

## Notes

- 文件路径固定为 `dataDir/logs/server.log`，默认即 `%LOCALAPPDATA%\TrellisBoard\server\logs\server.log`。
- 日志保留策略已确认为 `5 MiB × 5`。
- 任务已按本 PRD 完成实现和验证。
