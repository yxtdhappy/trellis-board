# E2E 验证报告：创建与改派操作忽略失败操作

- 日期：2026-11-20
- 被测代码：`8657410`（`feat(web): 创建与改派操作支持忽略已结束操作`）的 `packages/web` 构建产物
- 测试环境：隔离临时数据目录 + 端口 `4399` 的 team 模式服务；系统管理员 `e2e-admin`；
  项目 `E2E Demo Project` / 分支 `main`。未触碰本机 `4317` 运行中的服务与真实数据目录。
- 测试数据：通过测试库预置 5 条操作 —— `failed`、`cancelled`、1 分钟内的 `succeeded`、
  11 分钟前的 `succeeded`、`pending`；数据经真实 `/api/task-operations` 返回。
- 过程说明：任务归档发生在本报告之前；本报告是归档后补做的真实浏览器验收，代码无需修改。

## 结果

| # | 步骤 | 结果 |
| --- | --- | --- |
| 1 | 登录后选中项目分支 | 面板展示 4 条：`pending` 仅“取消”；`succeeded`（1 分钟内）仅“忽略”；`failed` 显示“重试”+“忽略”；`cancelled` 仅“忽略” |
| 2 | 检查成功项自动隐藏 | 11 分钟前的 `succeeded` 不在面板中；总条数未超过 8 条 |
| 3 | 点击失败行“忽略” | 该行立即消失，其他行保持原位；`localStorage['trellis.dismissed-operations.v1:e2e-admin:e2e-space']` 写入 `["e2e-op-failed"]` |
| 4 | 刷新页面并重新选择分支 | 失败项仍隐藏；进行中、近期成功、取消项正常显示 |
| 5 | 向本地记录注入已不存在的 ID `e2e-op-gone` 后刷新 | 记录被清理回 `["e2e-op-failed"]`，不存在的 ID 不再保留 |
| 6 | 调用 retry 把已忽略的失败项重置为 `pending` | 3 秒轮询内重新出现在面板，显示“等待客户端接管”+“取消”，无“忽略”按钮 |
| 7 | 将该操作再次改回 `failed` | 下一次轮询后重新隐藏，忽略记录保持 `["e2e-op-failed"]` |
| 8 | 覆写 `Storage.prototype.getItem/setItem` 使其抛错后刷新 | 页面正常渲染；点击“忽略”行立即消失（仅当前页面会话生效）；控制台无未捕获异常 |
| 9 | 恢复原生存储实现后刷新 | 重新按持久化记录隐藏失败项，状态与步骤 4 一致 |

## 关键结论

- PRD 验收项 1–7 均在真实浏览器中通过：已结束操作可忽略且立即隐藏；进行中操作无忽略入口且不会被隐藏；
  成功项 10 分钟自动隐藏保持；刷新与重新登录后忽略状态持久；状态未知的操作保持可见。
- 重试复用同一 operation ID 时，`pending` 状态不受忽略记录影响；再次失败后仍按原记录隐藏。
- `localStorage` 读取/写入异常时降级为会话内忽略，不影响页面渲染和操作。
- 忽略记录只保留服务端仍返回的操作 ID，不会无限增长。

## 验证限制

- 未接入真实 Agent 客户端监听；操作记录直接写入隔离测试库，但读取链路使用真实的
  `/api/task-operations` + 服务端归一化逻辑。
- 只验证了一个用户、一个 taskSpace；多用户/多 taskSpace 隔离由
  `packages/web/test/operation-visibility.test.js` 的存储键用例覆盖，并在浏览器中确认 key 包含
  当前用户名与 taskSpaceId。
- 测试期间首页显示的版本号为 `0.4.48`（来自并发发版），被测前端逻辑来自上述 `8657410` 构建。
