# 创建与改派操作面板支持忽略失败操作

## Goal

让「创建与改派操作」面板允许用户手动忽略已结束（成功 / 失败 / 取消）的历史操作，避免失败记录永久占据面板；忽略状态只影响当前浏览器。

## Context

- 现状：面板隐藏执行成功且超过 10 分钟的操作，但失败 / 取消操作永久保留，且没有删除或忽略入口。
- 服务端只有 `retry` / `cancel`，没有删除命令的 API；本需求不改服务端。
- 典型场景：一条指向已归档任务的改派命令反复失败后，面板永久显示红色失败项。

## Requirements

1. 已结束操作（`succeeded` / `failed` / `cancelled`）在同一行提供「忽略」入口；点击后该操作立即从面板隐藏。
2. 进行中操作（`pending` / `delivered` / `running`）不显示忽略入口，也不能被忽略状态隐藏。
3. 忽略状态按「当前用户 + taskSpace」持久化到当前浏览器的 `localStorage`：
   - 刷新页面、重新登录同一用户后仍生效；
   - 不同用户或不同 taskSpace 互不影响。
4. 已忽略的操作如果被重试并重新进入进行中状态，必须重新出现在面板（忽略记录只对已结束状态生效）。
5. 保持现有规则：`succeeded` 操作超过 10 分钟自动隐藏，无需用户忽略。
6. 忽略记录要随操作列表收敛：不再出现在服务端返回列表中的操作 ID 应从本地记录中清理，避免无限增长。
7. `localStorage` 不可用（隐私模式、配额满、读取异常）时页面必须正常工作，忽略退化为仅当前页面会话内生效，且不抛出错误。
8. 面板顶部最多展示 8 条可见操作的现有上限保持不变。

## Acceptance Criteria

- [ ] 失败和取消的操作单行出现「忽略」按钮；点击后该行立即消失，其他行不跳动到错误位置。
- [ ] 成功的操作同样提供「忽略」按钮，且原有“成功 10 分钟后自动隐藏”行为不变。
- [ ] 进行中操作没有「忽略」按钮；即使其 ID 在本地忽略记录中，也始终可见。
- [ ] 同一浏览器刷新后，已忽略的历史操作不再出现；切换用户或 taskSpace 后忽略列表独立。
- [ ] 已忽略的失败操作被重试进入 `pending` 后重新显示；再次失败后若仍在忽略记录中则保持隐藏，直到用户重新点击忽略前的状态不被破坏。
- [ ] 禁用或清空 `localStorage` 后，面板仍能渲染、忽略按钮可用、无控制台异常。
- [ ] 已从服务端列表消失的操作 ID 不再保留在本地忽略记录中。
- [ ] 可见列表逻辑有纯函数单元测试覆盖；`yarn --cwd packages/web build`、`oxlint` 通过。

## Out of Scope

- 不新增服务端删除 / 忽略 API，不做跨设备或跨成员共享的忽略状态。
- 不改变重试、取消、成功自动隐藏的服务端语义。
- 不追溯清理服务端历史命令记录。
