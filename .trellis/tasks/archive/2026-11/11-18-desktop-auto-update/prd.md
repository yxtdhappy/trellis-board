# 客户端自动更新与版本展示

## Goal

桌面客户端能够从配置的文件服务器检查、下载并安装新版本，安装后自动重启；Board 界面区分展示客户端版本与服务端版本；检测到新版本时弹出系统通知，点击通知可直接查看更新内容并执行更新。

## 背景

- 客户端当前只分发绿色 ZIP（`TrellisBoard_<version>_x64-portable.zip`），升级方式是在 README 里要求用户退出托盘、手工替换目录；没有任何更新检查入口。
- 对应任务的 `11-17-multi-client-task-sync-control-plane` 之后，客户端和服务端会独立发版，版本不一致是常态，界面上目前只显示客户端版本（`client_identity`），看不到服务端版本。
- `BoardPage` 的 `TopBar` 只在 Tauri 中显示 `v<clientVersion>`，浏览器访问时没有版本信息。
- 唯一已有的系统通知路径是 `HandoffNotice.tsx` 中的 Web Notification API，权限在 WebView2 中不可靠；更新通知需要官方插件保证可用。

## 范围

- 构建期可配置的更新服务器地址（环境变量 `TRELLIS_UPDATE_SERVER`），未配置则整个更新功能关闭。
- 更新检查（启动后、每 6 小时、手动触发）、版本比较、更新状态展示。
- 系统通知：发现新版本时通知；点击通知打开更新对话框。
- 更新对话框：显示客户端版本、服务端版本、更新服务器、最新版本与更新说明；下载、校验、替换、重启。
- 服务端 `/api/health` 返回版本号，Web 端展示服务端版本。
- 发布侧生成 `latest.json`，与便携 ZIP 一起上传到文件服务器。
- 不涉及：增量更新、代码签名/发布者校验、MSI/NSIS 安装器、更新服务器鉴权、运行时修改更新地址、自动回滚 UI。

## 功能需求

### F1 更新服务器配置

- 更新服务器地址只来自构建期环境变量 `TRELLIS_UPDATE_SERVER`，写入客户端二进制；终端用户无法在设置中修改。
- 地址为 http/https 绝对 URL，去掉末尾 `/` 后作为基地址。
- 未设置、空字符串或非法 URL 时，更新功能视为未启用：不发起任何网络检查、不发通知、托盘菜单项显示为不可用、更新对话框明确提示“未配置更新服务器”。

### F2 更新检查

- 客户端启动后自动检查一次；此后每 6 小时检查一次；用户可在更新对话框和托盘菜单手动触发。
- 检查读取 `<base>/latest.json`，与本机 `env!("CARGO_PKG_VERSION")` 比较，只有远端版本严格更高才算有更新。
- 检查失败（网络、HTTP 状态、JSON 结构、版本号格式、`sha256` 格式）不得崩溃或阻塞界面，错误显示在更新对话框中，并写入客户端日志。
- 检查结果（是否有更新、最新版本、更新时间、错误）缓存在内存中，供界面随时读取，不重复发起网络请求。
- 未启用更新时，手动检查直接返回“未配置更新服务器”。

### F3 版本展示

- 客户端 Board 顶栏在客户端版本号处显示客户端版本；该区域可点击打开更新对话框。
- 更新对话框同时展示三项：客户端版本、服务端版本、更新服务器地址（未配置时显示“未配置”）。
- 浏览器访问 Board 时不展示客户端版本，改为展示服务端版本；服务端版本来自 `/api/health` 的 `version` 字段。
- 服务端版本获取失败时只在界面省略，不报错、不阻塞 Board。

### F4 系统通知

- 仅在发现“比当前已通知版本更新”的版本时发送一次系统通知；同一版本不重复通知，重启后也不重复。
- 通知标题包含产品名，正文包含 `v<当前> → v<最新>`，点击通知打开更新对话框（聚焦主窗口）。
- 通知失败（权限、系统限制）只写日志，不影响检查结果和界面。
- 手动检查发现新版本时同样可以通知，但仍受同一版本去重约束。

### F5 更新对话框与安装

- 对话框打开时展示缓存状态并自动发起一次检查（已启用时）；检查中显示进度，已是最新时明确提示。
- 有新版本时展示最新版本号、发布时间、更新说明（保留换行）和“下载并更新”按钮。
- 点击更新后依次执行：下载 ZIP → 校验大小与 SHA-256 → 解压出客户端 EXE → 替换当前 EXE → 重启。
- 下载过程展示进度百分比；任何一步失败都停止并显示原因，当前客户端保持可用。
- 替换失败必须回滚到原 EXE；成功后自动退出并重新启动新版本。
- 开发模式（debug 构建）拒绝执行替换，提示“开发模式不支持自动更新”，避免破坏开发产物。

### F6 发布物

- `package-portable.ps1` 除现有 ZIP、`.zip.sha256`、`VERSION.txt` 外，额外生成 `latest.json`：
  `{ "version", "file", "sha256", "size", "notes", "publishedAt" }`。
- `file` 只能是 ZIP 的文件名（不允许路径分隔符或 `..`）；`sha256` 为 ZIP 的 SHA-256 小写十六进制；`size` 为字节数。
- CI 发布时把 `latest.json` 与 ZIP、`.zip.sha256` 一起上传；README 说明如何把这三个文件放到文件服务器，以及如何设置仓库变量 `TRELLIS_UPDATE_SERVER`。

## 非功能需求

- 网络请求超时：清单 15 秒，下载 10 分钟；下载分块写入磁盘，不整体读入内存。
- 更新检查不阻塞客户端启动和 Board 交互；检查与下载均在后台线程/异步任务中执行。
- 更新包只接受与清单一致的版本、大小和 SHA-256；ZIP 内只取唯一的 `trellis-board-client.exe`，不能写出目标目录。
- 未配置更新服务器时，客户端行为与当前版本完全一致（无额外网络请求）。
- 所有新增远程命令只能由已登录的 Board 页面调用，权限与 capability 显式声明。
- 新增文案使用中文，与现有界面一致；进度、错误使用现有 `alert`/`Progress` 组件。

## 验收标准

- [ ] 未设置 `TRELLIS_UPDATE_SERVER` 构建：启动后无任何更新网络请求；托盘“检查更新”不可用；对话框显示“未配置更新服务器”。
- [ ] 设置有效地址构建：启动后请求 `<base>/latest.json`；远端版本更高时状态为有更新，远端相同或更低时为已是最新。
- [ ] 发现新版本时收到一次 Windows 系统通知；点击通知打开更新对话框；同一版本重启后不再通知。
- [ ] 顶栏客户端版本可点击打开更新对话框；对话框同时显示客户端版本、服务端版本、更新服务器。
- [ ] 浏览器访问 Board 时顶栏显示服务端版本；`/api/health`（单机与团队）返回 `version` 且与 `packages/server/package.json` 一致。
- [ ] 使用本地文件服务器托管的 `latest.json` + ZIP 完成一次真实更新：进度显示、校验通过、EXE 被替换、客户端自动重启且版本号更新。
- [ ] 篡改 ZIP（哈希不匹配）、清单 404、清单字段缺失时，更新中止并显示错误，当前客户端仍可正常使用。
- [ ] 替换阶段模拟失败时原 EXE 被恢复（回滚路径有自动化测试覆盖）。
- [ ] `cargo test`、`cargo clippy --all-targets -- -D warnings`、`yarn build`、`yarn build:desktop`、`yarn test` 通过。

## 风险与约束

- 更新包没有代码签名，SHA-256 只能防止传输损坏；若通过公网 HTTP 分发，中间人可同时替换清单与包。文档要求使用 HTTPS 或可信内网文件服务器。
- Windows 上运行中的 EXE 可以重命名但不能覆盖，替换必须先改名再写入；杀毒软件可能短暂锁定文件，失败时回滚。
- 系统通知点击只在 toast 仍显示时可靠上报；进入操作中心后的点击无法回调，这是 Windows 平台限制。
- 自动重启要等旧进程释放单实例锁，直接启动第二个实例会交接给旧进程并退出。
