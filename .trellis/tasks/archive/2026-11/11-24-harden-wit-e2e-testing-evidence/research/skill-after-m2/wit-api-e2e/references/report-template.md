# 接口 E2E 验收报告与清单模板

> 报告落点：项目任务目录下的 `research/`、`docs/` 或项目指定位置；未生成报告文件不得宣布 E2E 完成。
> 本模板只覆盖接口阶段；页面渲染、交互、截图和 Console 证据由 `wit-ui-e2e` 报告承载。

## 0. 测试拓扑

| 层 | 地址 / 进程 | 说明 |
| --- | --- | --- |
| 本地转发代理 | `127.0.0.1:<proxy-port>`，PID；未使用时填“不适用” | local route、remote fallback、健康检查结果 |
| 后端 | `http://127.0.0.1:<backend-port>/<context-path>`，PID | 日志文件路径、启动时间、迁移/DDL 生效记录 |
| 数据库/中间件 | `<host>:<port>/<schema>`；未直连时填“通过接口读回” | 只写库名/用途，不写账号密码或完整连接串 |

需要页面联调时，页面入口和前端版本由 `wit-ui-e2e` 填写；本报告只证明“请求 → 代理 → 后端 → 日志/落库”链路。

## 1. 逐步证据表

| # | 请求 | 响应摘要 | 对应后端日志 | 验证层级 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 1 | `GET /api/xx` | code=20000，data.keys=… | 请求成功，无 ERROR | 契约级 | ✅ |
| 2 | `POST /api/yy`，参数 … | code=20000，id=… | 插入成功；回读一致 | 持久化级（已读回） | ✅ |
| 3 | 构造失败：… | code=…，文案可读，无 500 | 业务异常 `CODE`，无堆栈泄漏 | 契约级 | ✅（预期内） |
| 4 | 重复提交同一批次键 | 首次结果返回，无新增记录 | 幂等分支命中 | 持久化级（已读回） | ✅ |

每行都要「请求 → 响应 → 日志结论」三件齐；日志时间与请求时间对得上。后端确实没有请求级日志时，允许写“降级：响应 + DB/单测/副作用证据，原因 …”，并说明无法归因的部分；不得编造日志行，也不得把降级当完整证据。

## 2. 结论段

- 通过项：逐条写可核对的事实（列数、字段值、状态码、耗时）。
- 未通过项：现象 + 日志证据 + 已判定是脚手架还是代码缺陷 + 处理状态。
- 噪音说明：列出与本轮无关但日志里出现的告警（配置中心重连、心跳、探针等），注明与本次改动无关。

### 2.1 未验证项

逐条列出没有真机证据的部分，写明原因和后续动作。例如：只验证了预览/试算，未走写接口；未创建新对象；没有数据库访问权限；页面渲染未验证（交给 `wit-ui-e2e`）。未验证项不得写成通过。

## 3. 清理记录

- 本轮创建了哪些探针数据/表/账号，用什么方式删除，删干净没有（多副本环境逐副本确认）。
- 本轮创建的 token 文件是否已删除；用户已有的 token 文件是否保留并提醒轮换。

## 4. 验收清单回写格式

把结论直接写回需求/任务文档的验收项，每条附真机证据：

```markdown
- [x] <验收项>
      （<日期> 真机：<可核对事实>；后台日志：<请求> 结果 成功/预期内业务异常）
```

持久化类验收项必须有“写接口成功 + 读接口回读/查库确认”的双证据，才可以勾选；只有预览、试算、映射或写接口返回值时，保持未勾选并注明“未验证持久化”。

## 5. 报告禁忌

- 不写 token、密码、Cookie、完整连接串等凭据；不写未脱敏的请求/响应体。
- 不把 HTTP 200 当成业务成功；通过依据必须包含业务码/响应语义和日志证据。
- 不把未执行的验证写成已完成；未做的项明确写「未验证」。
- 不把预览、试算、映射类响应当作持久化证据。
- 不把页面渲染结果写进接口报告；页面证据交给 `wit-ui-e2e`。
- 不删归因证据后再补报告；先落报告，再清理临时文件。
