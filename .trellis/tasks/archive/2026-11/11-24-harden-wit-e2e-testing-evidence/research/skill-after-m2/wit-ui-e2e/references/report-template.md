# 页面 E2E 验收报告与清单模板

> 报告落点：项目任务目录下的 `research/`、`docs/` 或项目指定位置；未生成报告文件不得宣布 UI E2E 完成。
> 本模板只覆盖浏览器阶段；接口/后端日志/落库证据由 `wit-api-e2e` 报告承载。

## 0. 测试拓扑

| 层 | 地址 / 进程 | 说明 |
| --- | --- | --- |
| 页面 | `http://<frontend-host>:<port>/<path>` | 环境地址或本地 dev server；前端构建版本/启动时间 |
| 前端 dev proxy | `<frontend-port> -> <proxy-port>`；不适用时填“不适用” | `/appgw` 等前缀的转发表 |
| 本地转发代理 | `127.0.0.1:<proxy-port>`，PID；不适用时填“不适用” | 由接口阶段启动并验证，UI 报告只引用 |
| 后端 | `http://127.0.0.1:<backend-port>/<context-path>` 或环境地址 | 只写用途/版本；详细日志证据见接口报告 |

混合链路必须证明同一请求依次经过“页面 Network → 代理日志 → 后端日志”。缺少任一层证据时，不能把页面正常作为 E2E 通过；UI 报告可引用接口阶段报告的证据编号。

## 1. 逐步证据表

| # | 页面/路由 | 页面操作 | 期望 UI 状态 | 实际 UI 状态 | Network | Console | 截图 | 验证层级 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `/list` | 打开列表 | 表格 ≥1 行，列名正确 | 3 行；列名一致 | `GET /api/list` 200，code=20000 | 无新增 error | `01-list.png` | 页面级 | ✅ |
| 2 | `/list` | 点击「查询」 | 结果刷新，按钮可用 | 结果更新；按钮恢复 | `POST /api/query` 200 | 无新增 error | `02-query.png` | 网络级 | ✅ |
| 3 | `/edit` | 提交空必填项 | 明确提示，不提交 | 提示“名称不能为空” | 无请求 | 无新增 error | `03-required.png` | 页面级 | ✅（预期内） |
| 4 | `/edit` | 修改并保存后刷新 | 刷新后仍为新值 | 刷新后仍为新值 | `POST /api/save` 200；刷新 `GET` 返回新值 | 无新增 error | `04-persist.png` | 持久化级（页面侧） | ✅ |

每行都要「操作 → 页面变化 → Network/Console 结论」三件齐；截图与操作时间对得上。页面没有对应请求时，说明是纯前端交互还是请求未发出；不得编造 Network 行。

## 2. 结论段

- 通过项：逐条写可核对的事实（文本、元素数量、路由、状态码、截图编号）。
- 未通过项：现象 + 复现步骤 + 截图/Console/Network 证据 + 分类（选择器/环境/前端/后端）+ 处理状态。
- 噪音说明：列出与本轮无关但 Console/Network 里出现的告警（第三方脚本、既有 warning、探针等），注明与本次改动无关。

### 2.1 未验证项

逐条列出没有页面证据的部分，写明原因和后续动作。例如：未覆盖移动端视口；未测试无权限账号；未验证刷新后持久化；后端日志/落库证据未完成（交给 `wit-api-e2e`）。未验证项不得写成通过。

## 3. 清理记录

- 本轮通过页面创建了哪些探针数据/账号，用什么方式删除，删干净没有。
- 清理依赖接口/数据库时，记录由哪个接口阶段步骤完成；不把未清理写成已清理。

## 4. 验收清单回写格式

把结论直接写回需求/任务文档的验收项，每条附页面证据：

```markdown
- [x] <验收项>
      （<日期> 页面：<URL/路由>；操作：<点击/输入>；结果：<文本/元素/路由>；
        Network：<请求> <状态码/业务码>；Console：无新增 error；截图：<文件名>）
```

持久化类验收项必须有“页面刷新/回读 + 接口阶段写后读回/查库”的双证据，才可以勾选；只有操作瞬间的提示或页面局部更新时，保持未勾选并注明“未验证持久化”。

## 5. 报告禁忌

- 不写 token、密码、Cookie、完整请求头等凭据；截图和 Console 摘录同样不能带凭据。
- 不把「页面看起来正常」当成通过依据；通过依据必须有操作前后对照和 Network/Console 证据。
- 不把 HTTP 200 或页面提示当成业务成功；业务语义由响应摘要/接口阶段证据确认。
- 不把未执行的验证写成已完成；未做的项明确写「未验证」。
- 不把接口/后端日志证据写进 UI 报告冒充页面证据；需要时引用 `wit-api-e2e` 报告。
- 不删归因证据后再补报告；先落报告，再清理临时文件。
