# UI E2E Playbook

本 playbook 只覆盖浏览器阶段。接口契约、本机后端、代理、后端日志和落库验证使用 `wit-api-e2e`。

## 1. 开始前先回答三个问题

1. 页面来自哪个前端构建？是环境已部署版本，还是本地 dev server？
2. 后端最新代码跑在哪里？环境实例、本机进程，还是本地容器？
3. 本次要验证的验收项，哪些只能由页面证明，哪些需要接口/日志/落库证明？

三个问题不清楚时，先查构建产物、页面资源 hash、提交号、接口响应或问用户；不要直接开始点页面。

## 2. 三种运行场景

### 2.1 只改后端

- 页面继续用环境前端；本机启动最新后端，并由接口阶段确认浏览器请求已转发到本机。
- 先用一次页面请求 + 本地后端日志确认转发生效，再开始 UI 用例。
- UI 报告只写页面操作、Network、Console、截图；后端日志证据由接口阶段报告引用。

### 2.2 前后端都改、环境都没发

- 本地启动最新前端 dev server；由接口阶段启动最小代理，处理 `/appgw`、`/xxx-web` 等前缀。
- 浏览器访问前端 dev server 地址，不直接访问本地后端端口。
- 先确认“页面 Network → 代理日志 → 本地后端日志”三层出现同一请求，再做 UI 用例。
- 代理配置不写进 UI 技能；需要排障时回接口阶段。

### 2.3 前后端都已部署

- 直接访问目标环境页面，本地不起服务。
- 先确认页面资源版本/构建时间与本次发布一致，避免测到旧缓存。
- 仍按“基线 → 一次操作 → 操作后快照”记录，不因为环境稳定就省略 Console/Network。

## 3. Chrome DevTools MCP 操作顺序

1. 列出当前页面/标签，优先复用用户已登录的窗口；需要隔离时开新标签，但不要另开无会话 profile。
2. 打开目标 URL，等待页面稳定（目标元素出现/加载指示消失），记录最终 URL、标题、视口。
3. 清空或记录 Console/Network 基线；既有错误单独标注，避免算到本次操作头上。
4. 用稳定选择器定位元素：`data-testid`、`role`、`aria-label`、可见文本优先；避免随机 class、绝对 XPath、随数据变化的 nth-child。
5. 操作前读取目标元素状态（可见、可点击、文本）；操作一次；等待可判定状态（文本变化、元素出现/消失、请求完成），不用固定 `sleep` 代替。
6. 操作后读取 DOM/文本/属性、对应 Network 请求、Console 新增错误、截图。
7. 把证据写入报告；截图文件名带用例编号，说明只写页面状态。

## 4. 证据格式

每个用例至少包含：

| 字段 | 内容 |
| --- | --- |
| 页面/路由 | 操作前 URL、操作后 URL |
| 操作 | 点击/输入/选择的元素与值（凭据不写） |
| 期望 UI 状态 | 文本、元素数量、可见性、路由、样式类 |
| 实际 UI 状态 | 操作后实际读取值 |
| Network | 方法、URL（query 脱敏）、状态码、响应摘要 |
| Console | 操作前后新增 error/warning；既有噪音单列 |
| 截图 | 基线、操作后各一张，文件名 |
| 验证层级 | 页面级/网络级/持久化级 |
| 结论 | 通过/失败/未验证 + 分类 |

## 5. 断言清单

- 目标元素存在且可见；操作后文本/属性/数量符合预期。
- 路由/URL 符合预期；弹窗打开/关闭状态正确。
- 对应请求已发出；状态码和业务语义符合预期（业务失败不能只看 HTTP 200）。
- Console 无本次操作新增 error；有 warning 时判断是否预期。
- 刷新页面或重新进入路由后，数据仍符合预期（持久化级的页面侧证据）。
- 失败提示可读，不白屏、不吞错、不泄露凭据。
- 空态/加载态/错误态至少覆盖一个关键分支。

## 6. 常见坑

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 元素找不到 | 选择器依赖随机 class/序号、iframe/shadow DOM、动画未结束 | 换稳定选择器；先定位 iframe/shadow root；等待可见 |
| 点击无反应 | 被遮挡、禁用态、事件未绑定、路由未就绪 | 检查遮挡/disabled/Console；等待可点击 |
| 页面不更新 | 前端缓存、请求未发、响应业务失败、状态未刷新 | 看 Network/Console；刷新/走刷新入口；后端问题交接口阶段 |
| 请求打到旧后端 | 代理未生效、dev server 缓存、浏览器直连环境 | 回接口阶段确认三层链路；清缓存/重启 dev server |
| 登录态失效 | token 过期、环境切换、Cookie 域不匹配 | 让用户重新登录；不要从浏览器存储提取/复制 token |
| 截图正常但验收失败 | 只看了渲染，没核对 Network/Console/刷新后状态 | 补网络级/持久化级证据 |
| 弹窗/抽屉关闭后状态丢失 | 组件卸载、未提交、请求失败 | 看 Network 和 Console；区分前端状态与后端落库 |

## 7. 失败分类

1. **选择器/脚本问题**：元素定位、等待条件、iframe/shadow DOM、测试数据不对。修正后重跑，不记产品缺陷。
2. **环境/链路问题**：页面/登录/代理/缓存/版本不对。修正链路后重跑；请求是否到本机后端由接口阶段证据确认。
3. **前端缺陷**：渲染、交互、Console 异常、Network 成功但页面不更新。记录复现步骤和证据，交开发修复。
4. **后端/接口缺陷**：Network 4xx/5xx 或业务失败。回 `wit-api-e2e` 用接口用例复现并抓后端日志，不在 UI 层猜原因。

## 8. 退出标准

- 每条验收项都有页面级证据；涉及网络的有关联请求；涉及持久化的有刷新/回读或接口阶段双证据。
- 失败项已分类，并写明是脚手架、前端缺陷还是后端缺陷。
- 未验证项逐条列出原因，不写成通过。
- 报告已落盘，截图/Console 摘录可追溯，且不含凭据。
- 需要后端日志/落库证据的部分，已交给 `wit-api-e2e` 并拿到结论，或明确标为未验证。
