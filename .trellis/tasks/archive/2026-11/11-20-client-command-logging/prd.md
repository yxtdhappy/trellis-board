# 客户端命令报错可读性与日志留存

## Goal

客户端在中文 Windows 上把子进程报错原文展示给用户，不再出现乱码；所有命令失败留下可追溯的日志；日志占用有硬上限，不随运行时间无限增长。

## Requirements

### 1. 报错可读

- 由子进程 stderr 产生的错误（典型：首次启动安装 Trellis CLI 失败）在界面展示为中文原文。
- 不使用替换符（U+FFFD）掩盖无法解码的内容。

### 2. 失败日志

- 客户端执行的子进程（npm / node / git / trellis CLI / python 等）失败时记录：命令及其参数、退出码或失败原因、stdout 与 stderr 的尾部内容。
- 覆盖失败形态：无法启动、等待失败、超时、输出超过大小限制、非零退出。
- 运行环境安装、状态检查、Node.js 路径设置失败同样记录错误码与错误消息。
- 日志写入失败不得改变命令执行结果，也不得让客户端报错或崩溃。

### 3. 脱敏

- 日志中的 Bearer 凭证、设备凭证、令牌、配对码字段值不得出现明文（沿用现有 `redact`）。

### 4. 轮转

- 单个日志文件达到 5 MiB 时轮转到历史文件；保留当前文件与 2 份历史，磁盘占用上限 15 MiB。
- 轮转失败（文件被占用、权限不足等）时继续向当前文件追加，日志不丢失、客户端不报错。
- 日志目录不变，应用内「打开日志目录」能看到当前与历史文件。

## Acceptance Criteria

- [ ] 中文 Windows 上制造安装失败，界面错误信息为可读中文，不含 U+FFFD。
- [ ] 执行一条必然失败的命令后，日志目录的当前日志文件包含该命令名与退出码（或失败原因）。
- [ ] 持续写入超过 5 MiB 后，当前文件重新从空开始增长，历史文件数量不超过 2，目录总占用不超过 15 MiB。
- [ ] 写入含 `Bearer <token>` 与 `"token": "<value>"` 的日志后，文件中查不到明文令牌。
- [ ] 日志目录不可写时，命令仍正常返回结果，客户端不报错。
- [ ] `cargo test --bin trellis-board-client -- process::tests` 通过；日志相关单元测试覆盖轮转与脱敏。

## Decisions

- 轮转采用在现有日志写入点自写大小轮转，不引入日志框架：现有写入点是唯一落盘路径且写入前做脱敏，换成 `tauri-plugin-log`、`tracing-appender` 等会绕过脱敏或在 `main` 增加 guard 生命周期，收益仅为按时间轮转，不满足「磁盘占用有硬上限」这一主要诉求。

## Notes

- 乱码与失败日志两部分实现已存在于工作区，本任务一并纳入验收。
