# 修复团队模式归档索引查询与分页

## Goal

修复团队模式下“归档索引”始终为空的问题，取消前端硬编码的 80 条展示上限，让用户能够按真实归档时间倒序、每页 20 条地浏览全部已归档任务。

## Background

本机当前 `board.sqlite` 已索引 629 条归档任务，但团队模式的统一任务查询未设置 `archived=true`。服务端默认按 `archived=false` 返回活动任务，前端随后再筛选 `task.archived`，因此归档页只能得到空列表。

该问题位于团队模式查询接线，不是项目关联、Git 同步或归档扫描失败。

归档页还在 [ArchiveView.tsx](D:/wit/trellis-board/web/src/features/board/ArchiveView.tsx:46) 硬编码 `.slice(0, 80)`。当前已有每页 20 条的本地分页，但只在排序后的前 80 条候选中翻页，因此最多只能翻 4 页。代码、测试和任务记录中没有发现“80 条”是产品要求的证据。

团队查询 API 已支持 `limit`、`nextCursor` 和 `total`，但当前游标按最后活动时间排序；归档页现有产品语义按真实归档时间排序。若要直接改为服务端分页，还需要把 `archivedAt` 纳入任务索引和服务端游标排序。

## Requirements

- 团队模式进入或刷新“归档索引”时，必须使用 `archived=true` 查询已归档任务，不得复用活动任务查询结果。
- 归档查询必须继承当前团队范围和项目选择；选择“全部项目”时查询当前团队范围内全部可读项目。
- 归档列表取消 80 条上限，使用服务端游标分页，每页 20 条，并显示服务端返回的总数。
- 归档任务按真实 `archivedAt` 倒序排列；相同时间按项目 ID、任务键倒序，保证游标翻页稳定。
- 服务端任务索引必须保存 `archivedAt`；数据库升级时回填已有归档任务，后续扫描持续更新。
- 归档搜索和负责人筛选必须在完整归档集合上由服务端执行，不能只过滤当前页。
- 负责人选项应覆盖当前归档筛选范围内出现过的负责人。
- 支持上一页和下一页；修改团队、项目、搜索词或负责人时回到第一页。
- 查询修订号变化或游标失效时清空旧游标并从第一页重新加载，不能展示跨版本混合结果。
- 打开归档任务详情时不得提供修改、派发或撤销等写操作。
- 活动任务流水线、团队视角、项目列表和现有同步机制的行为不得改变。
- 独立模式现有归档列表行为不得回退。

## Out Of Scope

- 不修改归档目录结构、项目接入或 Git 扫描语义。
- 不新增归档保留、导出或恢复能力。
- 不改变活动任务按最后活动时间排序和分页的现有语义。
- 不提供按页码任意跳转；游标分页只提供上一页、下一页和当前页数。

## Decisions

- 归档与活动任务使用独立查询状态，避免共享 `teamPage` 导致筛选、游标和刷新互相覆盖。
- 使用服务端游标分页，不全量加载归档后在浏览器分页。
- 分页大小固定为 20 条，不向用户提供可配置值。
- 数据库 schema 从 v8 升级到 v9，升级前保留可恢复备份。

## Acceptance Criteria

- [ ] 团队模式存在归档任务时，进入“归档索引”可看到任务，不再显示“0 / 共 0 条”。
- [ ] 同一项目下，活动任务不得出现在归档索引，归档任务不得出现在活动流水线。
- [ ] 切换项目后，归档列表只展示所选项目的归档任务；“全部项目”展示当前团队可读项目的归档任务。
- [ ] 归档总数超过 20 条时可使用下一页继续浏览，且不存在 80 条上限。
- [ ] 第二页及后续页按真实归档时间倒序稳定返回，上一页和下一页数据不重复、不遗漏。
- [ ] 刷新归档索引会重新执行归档查询；查询修订号变化后从第一页重新加载。
- [ ] 搜索任务名或证据、按负责人筛选在完整归档集合上正常工作，修改条件后回到第一页。
- [ ] 当前筛选范围的负责人选项完整，不只包含当前页出现的负责人。
- [ ] 点击归档任务可查看只读详情，详情和操作区不出现可成功执行的写操作。
- [ ] 归档时间按真实归档时间倒序展示。
- [ ] 独立模式归档索引保持现有行为。
- [ ] 自动化测试覆盖归档查询参数、`archivedAt` 索引、归档游标顺序、分页游标失效、负责人选项和 v8 升级到 v9。
- [ ] 浏览器验证包含首次加载、第二页、返回上一页、项目切换、搜索、负责人筛选和只读详情。
- [ ] 完成后执行相关测试、静态检查和一次最终构建。
