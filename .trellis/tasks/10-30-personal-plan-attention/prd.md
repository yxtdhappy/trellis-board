# 个人执行：计划与注意力

## Goal

让个人用户可以在不污染 Trellis 任务文件的前提下维护计划字段，并通过可组合视图快速回答“下一步该做什么”。

## Dependencies

- 无前置子任务。
- 以父任务 `.trellis/tasks/10-30-personal-execution-enhancements/` 的需求和总体设计为准。

## Confirmed Facts

- 当前 Board 已有扫描、阶段推导、项目/负责人/关键词筛选和任务详情。
- 当前 SQLite schema 为 v1，持久化仓库、人工阶段、扫描缓存和 board state。
- 现有任务身份 `taskKey` 包含当前相对路径，归档后路径会变化。
- 目标仓库 `task.json` 不应承载看板专属计划字段。
- 历史指标只从事件记录启用后累计。

## Requirements

- R1 任务可维护截止日期、里程碑和标签，并存储在 Board SQLite。
- R2 截止日期接受有效公历日期或空值；里程碑最多 100 字符；标签最多 10 个且自动去重。
- R3 用户可从任务卡片和任务详情进入同一个计划字段编辑器，成功后从 API 重新读回。
- R4 提供 P0/P1、临近截止、长时间未动、实现中、检查中的内置注意力视图。
- R5 自定义视图可组合优先级、阶段、标签、截止窗口和停滞天数；条件使用 AND。
- R6 自定义视图可命名保存、再次使用和删除；内置视图不可删除。
- R7 新增稳定执行身份，使任务归档后计划、标签和事件仍能关联；身份冲突时禁止写扩展数据并显示原因。
- R8 从功能启用时开始记录计划字段、人工阶段和扫描观察到的阶段变化。
- R9 事件必须包含类型、来源、操作者、发生时间、关联操作 ID 和前后值；事件不可删除或原地篡改。
- R10 首次纳管旧任务只写 `tracking_started` 基线，不生成迁移前阶段事件。
- R11 原 Trellis 流程、项目筛选、负责人筛选、搜索、父子关系及归档行为不得回归。
- R12 同一任务组的父子层级必须在团队视角、Kanban 和注意力队列中清晰可见；跨负责人展示时保留真实父任务上下文，不得把子任务误作父任务。

## Acceptance Criteria

- [x] 保存截止、里程碑和标签后刷新页面并重启服务，数据仍从 SQLite 读回。
- [x] 写计划字段后，目标仓库 `task.json` 字节内容不变。
- [x] 无效日期、超长文本、空标签或超过 10 个标签被拒绝，失败时不产生部分写入。
- [x] 从任务卡片和详情都能打开带当前值的计划字段编辑器；失败时保留输入。
- [x] 内置注意力视图可定位对应任务，自定义筛选组合结果稳定且与单项判断一致。
- [x] 保存视图在重启后仍存在；删除后不再出现在 API 响应和页面中。
- [x] 活动任务归档到新路径后，仍能按稳定身份读回计划字段和标签。
- [x] 人工阶段写入与 `stage_manual_confirmed` 事件在同一事务提交。
- [x] 扫描阶段变化写入 `stage_observed`；首次 v2 启动不补造旧阶段事件。
- [x] 旧任务在事件不足时显示“历史缺失”，不使用文件修改时间代替。
- [x] 团队视角只显示一个父任务组头，子任务在同一子树内缩进；Kanban 使用连续连接线；注意力排序不变且子任务可见父任务路径。
- [x] 父子组跨负责人拆分时仍标识真实父任务及负责人，任务数、按钮计数和打开/计划操作不回归。
- [x] 在 1416×659 短高度视口中，主执行面板不被无内容高度拉伸；创建任务标题、提示和“创建并派发”footer 首屏可见，长表单只滚动主体。
- [x] `npm test`、JavaScript 语法检查、真实 API 验证和浏览器页面验收通过。

## Out of Scope

- 阻断依赖、WIP 上限和 DoR/DoD 提醒。
- 撤销、指标和复盘视图。
- 写回目标仓库 `task.json`。
- 日历集成、协作提醒和通知推送。

## Product Decisions

- 计划字段属于 Board 本地增强，不属于 Trellis 流程事实。
- 注意力视图面向个人日常选择，不扩展为团队工作流引擎。
