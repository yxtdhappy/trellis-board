# 完成团队版发布与集成验收

## Goal

将核心服务、Windows Agent 和团队 Web 控制台集成为可部署、可回滚、可真实使用的团队版，并用实际 Git、账号和 Windows 同步流程完成验收。

## Dependencies

- 依赖 `11-03-team-core-service`、`11-03-windows-sync-agent` 和 `11-03-team-web-console`。
- 只有前三个子任务完成且各自验证通过后才能启动。

## In Scope

- 集成测试、跨模块契约核对和缺陷修复。
- 单机数据库到团队版的真实升级、备份、回滚演练。
- Node/Git/Python 运行前置检查、反向代理/HTTPS、环境变量和启动方式文档。
- Windows Agent 自包含分发包、用户级安装脚本、登录启动和卸载说明。
- 两名以上用户和至少一台 Windows Agent 的真实 E2E。
- 400 账号、200 在线用户、100 项目、10,000 任务快照和 400 Agent 连接的可重复容量测试。
- 安全验收、故障演练、运维手册和发布检查单。

## Out of Scope

- 重写前三个子任务的领域逻辑。
- 新功能、审批流、SSO、外部数据库或多地域高可用。
- 未经用户授权发布到真实公司环境。

## Acceptance Criteria

- [ ] 单机模式回归和团队模式完整自动测试通过。
- [ ] 空数据库通过服务器本机 CLI 创建首个系统管理员，HTTP 无首次注册入口。
- [ ] 至少两份 v3 数据库副本完成升级；失败注入可恢复到 v3 快照。
- [ ] 至少一个现有 repository 按保留 ID 的方式接入团队项目，升级后原任务阶段/标签/依赖仍能正确投影。
- [ ] 真实 Git 远端完成“成员 A 创建/委派 -> push -> 成员 B 接受 -> Agent ff-only 同步”。
- [ ] 新任务元数据为共享分支 `branch` 和空 `base_branch`，现有 `task.py start/archive` 分支校验不会误报自引用。
- [ ] 反向代理场景只在可信代理独占上游时开启转发头信任，并验证登录来源 IP 限速。
- [ ] `python -B` 执行不产生脚本树缓存，重复执行前后工具链摘要稳定；脚本目录中的链接、`__pycache__`、`.pyc/.pyo` 和批准后任何文件变化都会被拒绝。
- [ ] 新项目在 `provisioning` 状态不可读任务或写入，只有管理员确认 scripts 摘要、hooks 预检通过并指定首个负责人后才启用。
- [ ] 分支校验拒绝 `HEAD`、`@{-1}`、前导 `-` 和 refspec 字符；本地 ignored 文件将冲突时 Agent 拒绝覆盖。
- [ ] 制造 dirty、错分支、并发版本冲突、推送失败和 `needs_repair`，界面、操作重试、管理员 repair 与本地仓库均保持可恢复。
- [ ] Agent 分发包在没有开发工具链的干净 Windows 用户环境完成安装、启动、同步和卸载。
- [ ] 目标容量压测达到既定吞吐和响应时间，不出现数据丢失、重复发布或串项目。
- [ ] 跨项目扁平查询、单项目分组分页、服务端筛选、ETag 和 3 秒状态轮询在 200 个 Web 会话下通过，不广播全系统任务正文。
- [ ] 运维文档包含备份、恢复、凭证轮换、Agent 撤销、项目下线、升级和回滚步骤。
- [ ] 不提交或发布真实密码、令牌、Cookie、Git 凭证和服务器绝对路径。
