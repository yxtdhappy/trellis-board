# 发布与集成验收设计

## 目标环境

服务端保持跨平台 Node.js 24 应用，MVP 至少在当前 Windows 环境完成真实部署验证；Git 和 Python 为任务写入前置。客户端首版仅支持 Windows 10/11 x64。TLS 由公司内部反向代理终止。

反向代理的读超时必须高于 Agent 25 秒长轮询，至少配置为 35 秒，并限制请求体大小。
- 反向代理访问日志不得记录 Cookie、Authorization、配对码或完整请求体；HTTPS 终止后保留外部 Host，并只把流量转发到回环监听。

## 发布物

| 发布物 | 内容 |
| --- | --- |
| 团队服务包 | 应用源码、依赖校验、启动脚本、环境变量模板、检查脚本 |
| 数据库迁移包 | v3 备份、v4 迁移、失败恢复和校验步骤 |
| Windows Agent 包 | Agent 源码/打包文件、官方 Node 24 x64 运行时、`trellis-agent.cmd`、启动/安装/卸载脚本和校验和 |
| 运维手册 | 部署、配置、备份、恢复、凭证轮换、项目接入、Agent 撤销和回滚 |
| 验收报告 | 自动测试、真实 E2E、容量、安全、故障演练和已知限制 |

发布包不包含真实 `.env`、数据库、日志、凭证、私钥或用户绝对路径。
未经代码签名时必须在包内提供 SHA-256，并通过公司可信渠道分发；SmartScreen 提示属于已知部署限制。

## 集成边界

- 核心服务对 Agent 和 Web 暴露已冻结协议；发布任务只修复集成缺陷，不在发布阶段重写领域规则。
- Web 和 Agent 共用协议版本与错误码，但分别拥有客户端错误文案。
- Agent 包随附官方 Node 24 Windows x64 二进制和校验和，避免要求每个开发机预装 Node；不自动安装 Git/Python，因为它们属于本地开发前置。
- 使用公司内部 CA 时必须分发可校验的 CA 文件并通过 `NODE_EXTRA_CA_CERTS` 信任，不能关闭 Node TLS 校验；Agent 安装检查会验证服务端证书链和主机名。
- 服务端要求 Node 24、Git、Python 可用，并在启动检查中明确缺失项。

## 数据迁移与回滚

1. 停止旧服务并确认无写请求。
2. 备份数据库、WAL/SHM、应用目录和环境配置。
3. 在数据库副本上运行 v3 -> v4 迁移与完整性检查。
4. 启动 team 模式，验证登录；项目首次接入必须经 `provisioning` scripts 摘要确认后才进入 `current` 并出现在看板。
5. 失败时停止服务，恢复 v3 快照和旧应用；保留失败数据库与日志用于诊断。

回滚不删除 Git 远端任务，不强制撤回已成功推送的提交。团队审计和任务接受状态随数据库快照回滚。
运维验收还要演练 `needs_repair`：人工修复受管副本后由系统管理员触发 repair，服务端按 operation trailer 对清远端/本地状态；不可安全恢复时保持阻塞。

## 真实 E2E

使用独立临时裸仓库并以 `file:` URL 接入，准备两个账号；测试实例显式开启 `TRELLIS_TEAM_ALLOW_LOCAL_GIT_REMOTES=true`，生产配置保持关闭：

1. 管理员接入临时项目，核对 scripts 摘要、通过 hooks 预检并指定首个负责人。
2. 负责人/成员 A 登录并创建任务，委派给成员 B。
3. 服务端提交并推送该项目约定的共享分支。
4. B 登录看到待接受并接受。
5. B 的 Windows Agent 在干净、分支匹配的仓库执行 ff-only 同步。
6. 本地读取任务文件并核对 assignee、`branch=<约定分支>`、`base_branch=null`、提交号和远端 HEAD。
7. 制造 dirty、ignored 文件冲突、sparse checkout、错分支、并发版本变化、脚本工具链摘要变化、lifecycle hooks、push 失败和凭证撤销，验证全部拒绝或可恢复。

## 容量测试

- 生成 400 账号、100 项目和 10,000 当前任务快照。
- 模拟 200 个在线 Web 会话、200 个 3 秒状态轮询和 400 个 Agent 心跳/长轮询（每名在线用户按 2 台设备留余量），记录 p50/p95、SQLite 锁等待、事件循环延迟、内存和扫描耗时。
- 默认路径持续执行跨项目分页查询和筛选，另外读取单项目分组页；验证 `team_task_index` 换版、`queryDay` 跨日、409、ETag/304、权限收窄和项目切换不串数据。
- 同时执行团队看板读取、100 项目有界 fetch 调度和每项目串行任务写，验证无重复幂等发布、无丢失审计。
- 超过 60 秒心跳阈值、500ms 常规读取或明显写锁级联时记录为待优化项；是否阻塞发布按是否影响业务正确性判断。

## 安全验收

- 登录/会话撤销、四角色矩阵、跨项目访问、CSRF Origin、输入大小限制。
- 个人保存视图/WIP/撤销隔离，以及旧阶段、计划字段、标签、依赖接口的授权与审计。
- SQLite、日志、审计、错误响应、Git 命令输出和进程 argv 的敏感值扫描。
- 任务路径越界、任务文件符号链接逃逸、slug/identity 冲突、脚本工具链摘要、lifecycle hooks、任意 Git 参数和任意 Shell 注入。
- Agent DPAPI、凭证撤销、远端 URL 归一化和 dirty 工作区保护。

## 运维

- 提供环境模板和启动/停止/健康检查脚本。
- 提供每日数据库备份、保留策略和恢复演练记录。
- 提供 Git 凭证轮换、Agent 凭证撤销、成员移除和项目下线步骤。
- 提供日志位置、关联 ID 查询和常见故障处置。
