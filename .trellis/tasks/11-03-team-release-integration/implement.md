# 发布与集成实施计划

## 前置

- 核心服务、Windows Agent、Web 控制台的实现与检查报告均已完成。
- 确认当前分支包含全部子任务提交，工作区没有无关改动。
- 未经用户明确授权，不向公司真实环境发布、不推送真实项目分支、不创建真实账号。

## 步骤

1. **集成核对**
   - 核对 schema、API、错误码、协议版本、任务身份和权限契约。
   - 运行一次完整 `npm test`、全部 JS `node --check` 和启动检查。

2. **迁移演练**
   - 使用 v3 数据库副本执行升级、完整性检查和 standalone/team 启动。
   - 注入迁移失败，验证 v3 快照恢复。
   - 从空数据库执行本机 CLI 创建首个管理员，并确认 HTTP 无首次注册入口。

3. **本地真实 E2E**
   - 用临时 Git 裸仓库启动 team 服务。
   - 通过 Chrome DevTools MCP 完成两用户创建/委派/接受。
   - 启动 Windows Agent 完成 ff-only 同步，并逐项测试 dirty、错分支、409、push 失败和撤销。

4. **Agent 分发**
   - 生成包含固定 Node 24 x64、`trellis-agent.cmd`、哈希、安装/卸载脚本和说明的 zip。
   - 验证 CLI 完成配对、绑定、状态和诊断，不依赖开发机预装 Node。
   - 在干净 Windows 用户配置中安装、登录启动、同步和卸载。
   - 验证包内无凭证、数据库和开发机绝对路径。

5. **容量与安全**
   - 执行 400 账号、100 项目、10,000 任务基线，以及 200 Web 会话和 400 Agent 心跳/长轮询压测。
   - 验证跨项目扁平查询、单项目分组分页、服务端筛选、游标换版、ETag/304、3 秒状态轮询和 100 项目有界 fetch 调度。
   - 记录看板、写入、扫描和 SQLite 指标。
   - 执行敏感值、路径越界、权限矩阵和命令注入检查。

6. **文档与发布候选**
   - 完成部署、运维、恢复、回滚、Agent 管理和常见故障手册。
   - 输出发布候选清单、已知限制和建议的灰度顺序。

## 完成门槛

- [ ] 全部自动测试和语法检查通过。
- [ ] 单机/团队两种模式真实启动通过。
- [ ] 数据库升级和回滚演练有命令、日志和结果。
- [ ] 真实“创建/委派 -> push -> 接受 -> Agent 同步”通过。
- [ ] 失败场景不覆盖本地文件、不强推、不产生 false success。
- [ ] Agent 分发包在干净 Windows 用户环境可用。
- [ ] 目标容量数据有记录，严重锁等待或内存问题已定位。
- [ ] 运维手册足以让另一名工程师独立部署、恢复和撤销设备。
