# 优化任务同步目录校验与错误展示

## Goal

让 Windows 客户端稳定接收合法的团队任务目录，修复 `\\?\` 扩展路径与普通绝对路径混用造成的假阳性越界；同时让同步错误明确显示项目、分支和诊断 ID，而不是只显示裸 `taskSpaceId`。

## Background

- 2026-11-13 16:24，客户端重启后从本地 cursor revision `99` 追赶服务端 revision `102`。
- 失败任务空间 `5efbba95-fdb1-4d09-bac1-dce7f11355c0` 对应项目 `mdp-backend-web`、分支 `dev`。
- 服务端快照中的任务目录均为合法的 `.trellis/tasks/...` 相对路径，没有目录穿越或绝对路径。
- 当前 Rust 路径解析只对 `.trellis/tasks` 根做 `std::fs::canonicalize`，目标任务仍使用普通绝对路径；Windows 上两者分别呈现为 `\\?\D:\...` 和 `D:\...`，组件比较因此误判。
- 控制窗口事件当前只携带 `taskSpaceId`，界面因此直接渲染 UUID。

## Requirements

### R1 跨端身份与路径职责

- 服务端任务身份继续使用 `taskSpaceId + taskDir`，其中 `taskDir` 是统一使用 `/` 的仓库相对路径 `.trellis/tasks/...`。
- 本机绝对仓库路径只在当前客户端内使用，不进入服务端协议、控制事件或错误日志。
- 不同客户端可以映射到完全不同的本地路径；同步逻辑不得依赖客户端之间的路径相同。

### R2 本机任务目录解析

- 客户端必须把服务端 `taskDir` 安全映射到当前 binding 的 `.trellis/tasks` 下。
- 解析必须拒绝空目录、`.trellis/tasks` 根本身、`.`、`..`、空路径段、反斜杠、NUL、绝对路径、Windows 盘符替换及其他可能逃出任务根的形式。
- 路径校验不得依赖只规范一侧的绝对路径比较；合法的 `D:\...` 与 `\\?\D:\...` 两种本地根形式都必须正常工作。
- 任务目录写入、删除和备份必须复用同一本机解析规则，并在路径无效或经过符号链接时失败关闭，不得静默跳过。

### R3 同步失败展示

- `task_sync_error` 应携带可读的项目名称、分支名称和可选任务目录；`taskSpaceId` 仅作为诊断信息。
- 控制窗口的主信息显示为 `项目 / 分支`，例如 `mdp-backend-web / dev`。
- 错误文案使用“任务目录路径校验失败”等具体描述，不能把所有路径问题笼统描述为服务端“越界”。
- 事件字段采用增量兼容：旧事件缺少项目或分支时回退显示 `taskSpaceId`，不能导致控制窗口白屏。

## Acceptance Criteria

- [ ] 合法的 `.trellis/tasks/...` 在普通 Windows 路径和 `\\?\` 扩展路径根下都能解析到同一逻辑任务目录。
- [ ] 根本身、`../`、绝对路径、反斜杠、空路径段和盘符替换均被拒绝。
- [ ] 无效任务目录不会写入、删除或备份本地内容，也不会推进 cursor。
- [ ] 本次 revision `100`～`102` 的归档目录变更可由回归测试覆盖并按服务端 revision 完成收敛。
- [ ] 路径错误弹窗显示 `项目 / 分支`，例如 `mdp-backend-web / dev`；UUID 只作为次级诊断信息。
- [ ] 控制事件和日志不包含本机绝对仓库路径。
- [ ] 旧版 `task_sync_error` 事件仍能显示，缺字段时回退到 `taskSpaceId`。

## Out of Scope

- 不改变 taskSpace、项目、分支或 revision 的服务端身份模型。
- 不在本任务中增加 macOS/Linux 客户端打包、系统安装器或真实跨系统 E2E。
- 不修改任务冲突、备份恢复或任务合并策略。
- 不清理本地 cursor、服务端任务空间或用户现有任务数据。
