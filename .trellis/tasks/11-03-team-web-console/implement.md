# 团队 Web 控制台实施计划

## 前置

- 等待核心服务认证、权限和团队 API 可真实调用。
- 阅读现有 `public/index.html`、`public/app.js`、`public/styles.css` 和前端规范。
- 保持原生技术栈；不引入框架、组件库、构建步骤或 CDN。

## 步骤

1. **共享渲染安全**
   - 抽出 `public/dom.js` 的 `escapeHtml`，让现有 `app.js` 以别名继续使用 `safe`。
   - 先做行为不变的页面回归，再新增团队页面。

2. **登录与会话**
   - 新增登录页、临时密码首次修改、认证请求、CSRF/Origin 错误提示和 401 跳转。
   - standalone 启动路径不请求认证接口。

3. **团队看板**
   - 接收 `/api/runtime` 的用户/角色能力，展示团队状态、stale 和待接受入口。
   - 默认用 `/api/tasks/query` 跨项目混合分页；选择项目后改用 `/api/board` 显示分组。项目摘要用于切换和状态，筛选、排序和总数交给服务端。
   - 跨项目结果用扁平卡片并显示项目徽标；单项目保留现有父子分组和泳道。
   - 3 秒轮询 `/api/team/status`，只有 `queryRevision`、`queryDay` 或当前项目 `boardVersion` 变化才刷新任务页；复用现有创建/委派对话框。
   - 补充 `taskVersion`、发布中、失败重试和分页状态。

4. **管理员与项目成员**
   - 新增管理页，覆盖用户、项目、成员、developer ID、脚本工具链摘要、hooks 状态和 Agent 绑定。
   - 一次性凭证只显示一次，浏览器不持久化。

5. **错误与可访问性**
   - 统一 401/403/409/502/503 展示和焦点管理。
   - 检查 `safe()`、Markdown、对话框、键盘和 reduced-motion。

6. **真实浏览器验收**
   - 使用 Chrome DevTools MCP 在真实服务上分别以管理员、负责人、成员和只读成员登录。
   - 制造 stale、Agent 离线、dirty、409 和 push 失败，确认 UI 可恢复。

## 完成门槛

- [ ] standalone 页面外观和交互不回归。
- [ ] team 未登录无法看到任务数据，401 自动跳转。
- [ ] 四类角色只看到允许控件；越权请求仍有 403 提示。
- [ ] 保存视图/WIP 只在当前账号内生效，不显示其他用户的个人状态。
- [ ] 项目切换和分页不会串项目，筛选作用于完整项目结果而不是当前页。
- [ ] 默认跨项目列表可混合多个项目，游标换版 409 自动重取且无重复/遗漏。
- [ ] `queryDay` 跨日、内置今日焦点和保存视图筛选与服务端结果一致。
- [ ] 创建/委派/接受/失败重试均显示服务端真实结果。
- [ ] 所有网络文本经共享 `escapeHtml()`，Markdown 不绕过既有函数。
- [ ] 1440px 和窄屏浏览器验收、键盘操作和控制台检查通过。
- [ ] 不保存密码、Cookie、Agent 凭证或 Git 凭证到 localStorage/sessionStorage。
