# 团队 Web 控制台技术设计

## 边界

复用现有原生 HTML/CSS/ESM 和看板渲染，不引入框架或构建链。Web 层只负责呈现服务端权限和状态；任何角色、项目访问、任务版本或 Git 发布判断都以服务端结果为准。

## 页面结构

| 文件 | 职责 |
| --- | --- |
| `public/login.html` / `public/login.js` | 登录、统一错误提示和成功后跳转 |
| `public/admin.html` / `public/admin.js` | 系统管理员用户/项目管理、负责人成员与 Agent 管理 |
| `public/index.html` / `public/app.js` | 现有看板；团队模式增加身份、待接受、同步状态和发布错误 |
| `public/team.css` | 只放团队页面使用的布局和状态样式 |
| `public/dom.js` | 共享 `escapeHtml`，现有 `app.js` 与团队页面共同使用 |

不做第二个全局设计系统。颜色、间距、按钮、对话框和响应式断点复用 `public/styles.css`。

## 启动与会话

- 服务端在 team 模式把未认证的 `/` 重定向到 `/login.html`；临时密码账号先进入改密界面，完成后再回到 `/`。
- `app.js` 启动时请求 `/api/auth/me` 和 `/api/runtime`；401 清理本地状态并跳转登录。
- `runtime` 只返回模式、当前用户、系统能力和项目角色，不返回密码、绝对路径或内部配置。
- standalone 模式不请求团队接口，不显示团队控件，现有行为不变。
- team 模式隐藏本机项目管理和文件夹选择入口；项目集合、刷新和错误只使用团队 API。

## 团队看板

- 默认“所有项目”范围调用 `/api/tasks/query`，返回跨授权项目的分页扁平任务行；选择具体项目后调用 `/api/board?projectId=...` 显示完整父子分组。
- 项目摘要来自 `/api/team/projects`，用于项目切换、计数和同步状态；跨项目任务行必须带项目徽标，点击后按 `projectId + taskKey` 打开详情。
- `/api/team/status` 约每 3 秒轮询一次，只返回轻量状态、项目 `boardVersion`、跨项目 `queryRevision` 和 `queryDay`；相关版本或自然日变化时才重新请求当前任务页。
- 两种任务页默认 100 条、最多 200 条；切换范围、项目或筛选条件时清空旧游标。筛选、排序和总数由服务端在完整授权结果上执行，不能只过滤当前页。
- 任务页使用 `ETag`/`If-None-Match`；304 不替换当前列表，但更新同步状态。跨项目游标返回 409 时清空分页状态并从第一页重取，不拼接两个索引版本。
- 显式项目筛选包含无权项目时显示 403 并清空该筛选，不静默混合其他项目结果。
- 保存视图和 WIP 由服务端按当前账号返回；UI 不把“个人视图”展示成团队共享配置。
- 顶栏增加项目 Git 同步时间、stale 警告和待接受数量；状态由 `/api/team/status` 批量提供，禁止逐项目 N+1 请求。
- 创建任务对话框继续使用现有 slug/标题/描述校验，但负责人列表改为当前项目的有效 Trellis 成员。
- 团队模式隐藏或锁定“目标分支”输入，并明确显示项目绑定的共享分支。
- 委派使用任务当前 `taskVersion`；409 后重新拉取详情，不自动覆盖。
- Git 发布失败展示错误码、操作 ID 和调用重试接口的入口；成功前按钮保持发布中状态。
- 收到 202 后按操作 ID 退避轮询状态，达到 `applied` 才显示发布完成，`failed` 显示可操作错误。
- 每个逻辑创建/委派操作生成一次 `idempotencyKey`，网络失败重试复用该值，用户修改表单后再生成新值。
- “待我接受”抽屉复用一个列表；接受携带当前 `assignmentVersion`，成功后更新任务状态，409 时重新拉取。
- assignee 无法映射到项目写成员时显示阻塞标记和“负责人无效”，不显示可用的接受结果；有写权限的负责人仍可重新委派。

## 管理页面

- 用户管理：创建、禁用、重置临时密码和撤销会话。
- 临时密码只在重置响应中显示一次，页面不写入本地存储、不进入日志或审计；关闭对话框后无法再次查看。
- 系统管理员可升级现有 `repositories` 行或创建新项目，并绑定远端/分支；服务端克隆后在管理页展示 scripts 摘要，管理员确认摘要并指定首个 `lead` 后才运行已批准脚本的 hooks 预检并在通过时启用。远端和分支自创建起只读；项目负责人可查看工具链/hooks 状态，并配置本项目的 `lead/member/read_only` 与 developer ID。
- `needs_repair` 项目显示阻塞原因和运维指引；只有系统管理员可触发 repair，普通刷新或重试不能绕过该状态。
- 角色编辑必须显示“最后一名项目负责人不能移除”的服务端校验结果；前端禁用只是提示，不替代授权。
- Agent 管理：查看设备、心跳、版本、绑定和撤销状态；负责人可确认/拒绝绑定。
- 危险操作使用确认对话框和明确结果，不在前端保存一次性凭证；配对码只在创建响应中显示。

## 渲染与安全

- 所有服务端文本使用共享 `escapeHtml()`；Markdown 继续只通过 `renderMarkdown()`。
- 动态内容后重新绑定事件，禁止把网络数据拼入事件属性。
- Cookie 由浏览器自动携带，前端不读取令牌；所有写请求显式设置 JSON Content-Type。
- 权限只决定控件是否显示，服务端仍必须重新授权。
- 错误状态使用 `role=alert`；加载和成功消息使用 `aria-live`，键盘焦点在对话框关闭后返回触发按钮。

## 响应式与兼容

- 保持 1440px 桌面布局；860px 以下采用单列抽屉和可横向滚动的紧凑状态栏。
- 保留 `prefers-reduced-motion`；不依赖悬停才能完成操作。
- 不引入外部字体、CDN 或远程脚本；断网时页面仍可登录和显示本地错误。

## 测试

- 登录成功/失败、会话过期、退出和 401 跳转。
- 四类角色下项目、按钮和路由可见性；服务端 403 仍能显示。
- 创建、委派、409、push 失败重试、待接受和接受闭环。
- stale、Agent 离线、版本过旧、dirty 和远端不可达错误。
- 跨项目/单项目切换、未授权项目参数、筛选、换版 409、空页和项目徽标不串数据。
- 浏览器桌面/窄屏、键盘、控制台、空状态和 standalone 回归。
