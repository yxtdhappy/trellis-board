# Git 凭据管理与项目接入远端识别

## Goal

管理员在团队管理中维护多套 Git 访问凭据，并在“项目接入”中为 HTTPS 或 SSH Git 远端选择对应凭据；系统使用该凭据自动带出项目名称和远端真实分支列表供选择共享分支，减少手工输入错误，同时让多个项目复用不同的 GitHub、GitLab 等仓库凭据。

## Background

- 实施前项目名称和共享分支都是文本输入，且位于 Git 远端 URL 上方：[OnboardingTab.tsx](../../../web/src/features/admin/OnboardingTab.tsx:247)。
- 实施前创建接口只接收管理员手工提供的 `name`、`syncBranch` 和 `remoteUrl`：[http.js](../../../server/team/http.js:976)、[projects.js](../../../server/team/projects.js:252)。
- 服务端已有 Git URL 规范化、分支校验和 `git clone` 能力；本次新增远端默认分支和 heads 探测：[git-manager.js](../../../server/team/git-manager.js:59)、[git-manager.js](../../../server/team/git-manager.js:931)。
- 实施前 Git 执行会禁用交互式 credential helper，且没有可在服务端维护的 Git 凭据实体、API 或管理页面：[git-manager.js](../../../server/team/git-manager.js:254)。
- 团队项目需要支持多仓库、多凭据：N 个仓库可以对应 M 套凭据，同一套凭据可被多个仓库复用，不同仓库可选择不同凭据。

## Requirements

- 表单调整为先展示 Git 远端 URL；“识别远端”按钮与 URL 输入框同一行并位于输入框右侧，再展示识别后的项目名称和共享分支。
- URL 输入框下方提供“Git 凭据”下拉框，选项包括“无需凭据（公开仓库）”和当前团队可用凭据；管理员必须在点击“识别远端”前明确选择，不做按主机模糊匹配或自动尝试多套凭据。
- 远端探测只由明确的“识别远端”按钮触发，不在输入、失焦或定时器到期时自动访问远端；再次点击可重新探测。
- 探测成功后自动回填可推导字段：项目名称使用仓库路径最后一段推导值，共享分支使用有效 symbolic `HEAD` 对应分支；没有有效 symbolic `HEAD` 时仅填充分支选项、不选择默认项。已有本地仓库 ID 等不可推导字段保持原值。
- 新增 Git 凭据管理页面和表单，至少支持新增、查看元数据、修改、删除；不得在查看接口或页面中回显凭据明文。
- 首版支持两类凭据：
  - HTTPS：用户名与访问令牌/PAT；
  - SSH：私钥与可选私钥口令。
- 每套凭据必须绑定一个明确 Git 主机，例如 `github.com` 或 `gitlab.company.com`；HTTPS 凭据只能用于 HTTPS URL，SSH 凭据只能用于 SSH URL，且 URL 主机必须与凭据绑定主机匹配。
- 凭据的主机和认证类型创建后不可修改；名称、HTTPS 用户名和秘密材料可以更新，秘密留空表示保持原值，更新秘密后所有引用项目立即使用同一凭据 ID 下的新值。
- SSH 凭据首次连接未知主机时，服务端获取并展示主机指纹，管理员确认后才保存信任关系；后续主机密钥变化必须拒绝连接并要求人工重新确认，不得自动信任或关闭严格主机校验。
- 凭据以独立实体保存并与项目解耦；项目接入时选择可用凭据，多个项目可复用同一凭据。
- 凭据按团队隔离并形成团队级共享凭据池；团队管理员只能维护和分配本团队凭据，系统管理员可以维护全部团队的凭据。
- 项目只能引用同一团队的凭据；跨团队引用必须被拒绝。
- 服务端使用自动生成在 `data` 目录下的固定主密钥加密凭据，不要求额外配置环境变量；主密钥必须限制文件权限并与数据库一起纳入备份。
- 主密钥只在首次需要时原子生成且不得覆盖；若主密钥缺失但数据库中已有加密凭据，服务端必须拒绝使用这些凭据并报告密钥丢失，不能静默生成新密钥。
- 远端探测、项目克隆、刷新、拉取和推送均使用项目选定的凭据；项目未选定凭据时仅允许访问无需认证的公开仓库，或要求先选择凭据。
- 服务端新增只读远端探测接口，校验团队管理员身份和 Git URL 后返回：
  - 推荐项目名称；
  - 远端默认分支；
  - 全部 remote heads。
- 项目名称从规范化仓库路径最后一段推导，去掉 `.git` 后缀，并允许管理员手动修改。
- 共享分支改为下拉选择，只能提交探测结果中的真实分支。
- 若无法解析出有效 symbolic `HEAD`，不按 `main`/`master` 猜测默认分支；共享分支保持未选择，管理员必须从真实分支中明确选择后才能提交。
- 创建项目时服务端仍重新执行分支和远端校验，不能信任前端探测结果。
- 远端变化后必须清空旧分支和旧推荐名称，防止把 A 仓库的分支提交给 B 仓库。
- 探测失败时禁止克隆提交，显示明确的认证、网络、URL 或分支错误。
- 探测请求必须设置超时、输出大小限制和并发/频率限制。
- 探测过程不得修改项目目录、数据库或执行项目脚本。
- 凭据明文不得出现在日志、错误信息、审计详情、前端状态或 API 响应中；服务端只返回名称、类型、归属、使用关系、创建/更新时间等非敏感元数据。
- Git 凭据仅供 Board 服务端使用，绝不下发到浏览器、桌面 Agent 或任务响应；桌面端本地仓库继续使用本机 Git 凭据。
- 凭据被项目引用后，删除、停用或替换必须避免刷新和推送悄悄切换到错误身份。
- 仍有项目引用凭据时禁止删除；管理员必须先让相关项目改用其他凭据或解除绑定。

## Out of Scope

- 不向浏览器、桌面 Agent 或任务接口下发 Git 凭据。
- 不支持同一项目在一次 Git 操作中自动尝试多套凭据或故障转移。
- 不支持凭据跨团队共享。
- 不实现 GitHub/GitLab 专用 API；统一通过 Git 命令读取远端 heads。
- 不实现主密钥轮换、批量凭据轮换、Git LFS 专用凭据或子模块独立凭据。

## Acceptance Criteria

- [ ] 输入 `https://github.com/example/repo.git` 后，点击按钮自动显示项目名称 `repo`。
- [ ] Git 远端 URL 位于表单最上方，“识别远端”按钮紧邻输入框右侧；普通输入和失焦不会发起网络请求。
- [ ] 探测前必须明确选择“无需凭据”或一套团队凭据；服务端不会自动尝试多套凭据。
- [ ] 输入等价的 SSH 地址后，项目名称推导结果一致。
- [ ] 远端分支以搜索/下拉方式展示，不要求手工输入分支名。
- [ ] 若远端可识别默认分支，默认选中该分支。
- [ ] 若远端无法识别有效 symbolic `HEAD`，不自动选择任何分支，管理员选择真实分支后才能提交。
- [ ] 管理员可以覆盖自动生成的名称，但最终创建仍通过服务端名称校验。
- [ ] 修改远端 URL 或凭据后，旧分支列表和旧自动名称不会残留。
- [ ] 私有仓库凭据不可用时显示可操作错误，不创建 `provisioning` 项目。
- [ ] 非法 URL、不可达仓库、无 heads 仓库和非团队管理员请求被拒绝。
- [ ] 探测接口只读，不产生 Git 工作副本、数据库记录或审计中的敏感凭据。
- [ ] 管理员可维护多套凭据，并让不同项目分别选择 GitHub、GitLab 或其他 Git 服务的凭据。
- [ ] 管理员可分别创建 HTTPS 用户名/访问令牌和 SSH 私钥/可选口令两类凭据。
- [ ] 凭据主机与 URL 主机或认证类型不匹配时，探测、克隆、刷新、推送和保存项目凭据关系均被拒绝。
- [ ] SSH 首次连接必须展示主机指纹并由管理员确认；主机密钥变化时连接失败且不会静默覆盖旧信任。
- [ ] 被项目引用的凭据不可删除，并明确展示引用它的项目。
- [ ] 多个项目可复用同一套凭据，已接入项目可以明确更换凭据或解除凭据。
- [ ] 团队管理员不能查看、修改或使用其他团队的凭据，系统管理员可以跨团队管理。
- [ ] 任何客户端接口都不返回已保存凭据的明文；凭据明文不会出现在页面、日志或审计记录中。
- [ ] 服务端 Git 凭据不会通过页面状态、桌面 Agent 协议或任何客户端接口下发。
- [ ] 已保存的 Git 凭据在数据库中只以密文存在，主密钥自动生成并保存在 `data` 目录。
- [ ] 凭据失效时，探测、克隆、刷新或推送返回可操作错误，不会退回匿名访问或使用其他项目凭据。
