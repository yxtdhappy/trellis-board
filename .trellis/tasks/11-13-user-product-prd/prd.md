# 生成面向用户的项目 PRD 文档

## Goal

基于当前项目源码和已归档 Trellis 任务，形成一份面向产品、业务和项目干系人的
Trellis Board 项目 PRD，清楚说明产品定位、目标用户、功能范围、设计思路、核心交互、
权限边界和当前不提供的能力。

## Background

- Trellis Board 当前同时支持 standalone 和 team 两种运行模式。
- 产品能力已从单机任务看板演进为包含个人执行控制、团队协作、Windows 客户端、
  任务空间实时同步、账号权限、项目审计和插件的多组件系统。
- 归档任务包含大量历史方案。部分方案已被后续实现替代，不能直接当作当前产品事实：
  - 服务端 Git 克隆/稀疏检出已被“客户端上传 tasks-only 快照”替代。
  - Node SEA sidecar 已被 Rust 单 EXE 进程内 Agent 替代。
  - 单活动团队切换已演进为默认“全部授权团队”聚合，并支持团队筛选。
- 当前源码、测试、README 和运维文档是现状事实来源；归档任务用于解释产品目标、
  约束、取舍和交互演进。

## Requirements

### R1 事实与来源

- 以当前源码和现行文档确认功能是否存在、当前状态和已知限制。
- 使用归档任务补充产品动机、设计原则、历史替代关系与关键交互决策。
- 对已被后续任务替代的历史方案，明确以“演进背景”表述，不得写成当前功能。

### R2 文档对象与表达

- 文档面向产品、业务、项目负责人、团队管理员和新加入的实施人员，不需要读者先理解内部代码。
- 使用简体中文，技术概念首次出现时给出产品语义。
- 重要能力要说明：解决什么问题、面向谁、用户如何操作、系统如何反馈、异常如何收口。
- 关键边界和限制必须明确，不把规划中或已淘汰的能力写成已交付能力。

### R3 内容范围

- 产品定位、问题背景、目标用户和使用场景。
- standalone 与 team 两种模式及其适用边界。
- 账号、团队、项目角色与权限模型。
- 任务发现、流程推导、个人执行控制、筛选、保存视图和注意力机制。
- 任务详情、阶段证据、条件检查、依赖、计划字段、任务产物和复制任务名。
- 任务创建、派发、待接受队列和 Web 到 Agent 的命令执行闭环。
- 项目列表、分支任务空间、跨项目/跨分支查询、归档索引和团队视角。
- Windows 客户端登录、环境门、本地项目接入、首次差异处理、Tasks-only 同步、
  冲突处理、分支门禁、双 worktree 约束和桌面分发。
- 管理台中的用户、团队、项目协作、Agent 设备和系统审计。
- 插件体系的产品价值、运行状态、日志和 standalone/team 边界。
- 设计思路、核心交互、状态反馈、异常处理、非功能要求和明确非目标。
- 关键源码与归档任务的证据索引，便于后续核验和更新。

### R4 输出与放置

- 正式文档写入 `docs/product-prd.md`。
- Trellis 任务目录保留需求、设计、实施和证据索引，不把计划过程混入正式 PRD。
- 正式 PRD 应可独立阅读；引用内部任务编号只作为证据索引，不作为正文叙事主线。

## Acceptance Criteria

- [x] `docs/product-prd.md` 已创建，且可从当前仓库直接阅读。
- [x] 文档明确区分当前能力和历史演进，不包含已被当前实现替代的错误功能描述。
- [x] 文档覆盖 R3 中列出的全部产品域，并为每类核心功能说明用户问题、
      设计思路和至少一个核心交互。
- [x] standalone 与 team 的差异、权限角色、任务空间、同步与冲突边界清楚可辨。
- [x] 文档列出当前非目标，包括评论、通知、审批流、SSO、多实例高可用和
      macOS/Linux Agent 等现行明确范围外能力。
- [x] 文档中的当前功能结论能追溯到现行源码或 README；关键历史决策能追溯到归档任务。
- [x] 文末证据索引至少覆盖当前源码入口和本次采用的核心归档任务。
- [x] 全篇使用简体中文，术语一致，不使用占位内容或 TBD。

## Out of Scope

- 不修改任何产品代码、服务端接口、数据库或配置。
- 不新增需求，不把历史任务中的未交付设想扩写为未来路线图。
- 不生成营销材料、投标文档、接口文档或详细技术设计文档。
- 本次不为文档引入新的构建、发布或自动化流水线。

## Notes

- 文档属于复杂信息归并任务，需在实现前完成 `design.md` 和 `implement.md`。
- 本任务只做文档交付，不执行代码构建；最终验证以文件存在、结构完整、术语和事实一致性为主。
