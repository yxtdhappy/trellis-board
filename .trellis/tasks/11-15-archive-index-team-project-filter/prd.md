# 归档索引增加团队和项目筛选

## Goal

让用户可以直接在归档索引页面按团队和项目收窄历史任务，两类筛选均使用带搜索的单选下拉，并且只影响归档索引本页，不改变顶栏团队或左侧项目栏的全局选择。

## Background

- 归档索引当前已有任务关键词、分支和负责人筛选，但页面内没有团队、项目筛选。
- 团队模式的任务查询接口已支持 `teamId` 和 `projectIds`，前端现有 `buildTaskQuery` 也会生成这两个参数。
- 顶栏团队和左侧项目栏维护的是全局 `filters.teamId` / `filters.projectId`；本次页面筛选需要独立维护，避免在查看历史归档时切换整个看板。

## Requirements

- 在归档索引筛选栏中，将团队、项目两个控件放在负责人筛选右侧。
- 团队和项目均使用带搜索能力的单选下拉，支持鼠标和键盘操作，并显示无匹配结果。
- 团队下选项包含“全部团队”和当前用户可访问团队；项目下选项包含“全部项目”和当前用户可访问项目。
- 团队筛选变化后，项目下拉只展示该团队下的项目；当前项目不再属于所选团队时，项目选择重置为“全部项目”。
- 页面筛选默认是“全部团队 + 全部项目”，不继承顶栏当前全局团队。
- 在归档页选择团队或项目只改变归档查询条件和分页结果，不调用全局 `setFilters`，不改变顶栏团队和左侧项目选择。
- 服务端查询沿用现有 `/api/tasks/query` 的 `teamId`、`projectIds`、`archived=1` 契约，不新增后端接口。
- 筛选变化、刷新和翻页时继续保留当前页面内的团队、项目和已有搜索条件。
- 保持现有归档任务搜索、分支模糊筛选、负责人筛选、分页与打开任务详情行为不变。

## Acceptance Criteria

- [x] 团队模式下，归档索引负责人筛选右侧显示“团队”和“项目”两个可搜索下拉。
- [x] 打开下拉后输入关键词，只保留名称匹配的团队或项目；无匹配时显示明确空状态。
- [x] 选择团队后，归档结果只包含该团队任务，项目选项同步限制为该团队项目。
- [x] 选择项目后，归档结果只包含该项目任务，并可从第一页开始正确分页。
- [x] 在归档页切换团队或项目后，顶栏团队与左侧项目栏的当前选择保持不变。
- [x] 刷新归档列表后，页面内团队、项目及其他现有筛选仍保持当前选择。
- [x] 现有任务关键词、分支、负责人筛选以及打开归档任务详情的功能没有回归。
- [x] 前端类型检查、lint 和项目测试通过；完成后按实际运行方式验证一次归档页筛选闭环。

## Out of Scope

- 不改变顶栏团队切换器或左侧项目栏的交互。
- 不新增多选筛选、筛选条件持久化、URL 同步或保存为组合视图。
- 不修改归档查询 API、数据库结构或任务数据模型。
- 不重新设计归档索引页其他区域。
